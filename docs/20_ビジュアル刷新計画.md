## 2. 全タスク共通ルール（ガードレール）

**[13の2節](13_M2実装計画.md)（さらに上流は [10の2節](10_F4-F6実装計画.md)）を全面的に継承する**。本計画での差分・上書きは以下のとおり。

### 2.1 ブランチ運用

- 作業は `task/V-x-説明` ブランチで行い、dev への **PR（ドラフト）** を作成する。着手時に `git fetch` して最新devから分岐する。
- V-3〜V-6は互いに独立なので並行着手してよいが、**共通CSS（tokens.css・components.cssの共有セレクタ）を追加変更したくなったら停止**する（V-1完了済みの共有面を各タスクが勝手に広げると衝突するため。自画面専用のクラス追加は自由）。

### 2.2 新規依存の方針

- **packages/app への新規 dependencies はゼロ**。devDependencies は導入済みの `playwright-core`（スクリーンショット確認用）のみ許可。これ以外が必要になったら停止して人間に確認。
- 画像・フォントの追加バイナリは V-8（キービジュアル）を除き禁止。SVGはインライン（JSX）で書く。

### 2.3 不変条件（毎タスクで回帰確認する）

1. **WCAG AA**: 新しい配色の組合せを作る場合、必ず機械計算（下記コントラスト計算式）で 4.5:1（本文）/ 3:1（大文字・UI部品）を確認し、計算値をコード内コメントに残す（tokens.cssの既存慣行）。
2. **二重符号化**: 正誤・状態表示に色単独の変更を持ち込まない（07の原則4）。
3. **モーション規律**: 常時アニメーション追加禁止。演出時間は07の9節の範囲内。`prefers-reduced-motion` で全て静止し情報が欠落しないこと（base.cssの既存全停止ルールが効いているかを確認）。
4. **正誤表示のレイアウト不動**: choice-button の状態変化は枠色・アイコン色のみ（既存テストが担保。壊さない）。
5. **タップ目標**: 既存の `--tap-min`（48px）・`--answer-height`（56px）を下回る操作要素を作らない。
6. **性能**: 学習中画面（S2/S3）に `filter: blur()` や大面積の `box-shadow` 多重掛けを置かない（低端末のGPU負荷）。光暈は3.1節の限定4箇所のみ。

コントラスト計算（Node一発。tokens.cssのコメント値と同じ算式）:

```js
node -e "function lum(h){const n=h.replace('#','');const a=[0,2,4].map(i=>{const c=parseInt(n.slice(i,i+2),16)/255;return c<=0.03928?c/12.92:Math.pow((c+0.055)/1.055,2.4)});return .2126*a[0]+.7152*a[1]+.0722*a[2]};function r(x,y){const s=[lum(x),lum(y)].sort((p,q)=>q-p);return((s[0]+.05)/(s[1]+.05)).toFixed(3)};console.log(r('#前景','#背景'))"
```

### 2.4 完了手順（全タスク共通）

1. ルートで `npm run lint`・`npm run format:check`・`npm run build`・`npm test` 全通過。
2. **スクリーンショット確認（必須）**: `npm run dev -w @beb-raid/app` を起動し、`node packages/app/scripts/screenshot-tour.mjs <出力先>` を実行（ダーク）、続けて `--light` 付きで実行（ライト）。**生成された画像を必ず自分の目で開いて確認**し、変更画面の見た目がモックアップの意図に沿っていること・他画面にレイアウト崩れが出ていないことを確認する。画像はコミットしない。
3. STATUS.md の本計画の節にタスク完了を追記（同じPR）。
4. シートの完了条件を1つでも満たせない場合、条件を勝手に緩めず停止して報告する。

### 2.5 停止規則

- シート・3節に無い設計判断（新しい画面構成・情報の増減・文言変更）が必要になったら停止する。
- 既存テストの期待値変更が「見た目のクラス名・DOM構造変更に伴う機械的追従」を超える場合（動作仕様が変わる場合）は停止する。

## 3. デザイン仕様

### 3.1 トークン（V-1実装済み。tokens.cssが正本）

| トークン | 用途 | 備考 |
|---|---|---|
| `--ev-blue` | ブランド表層の電光青。英字ラベル・ヒーローのアクセント・アイコン | 文字使用可（両テーマAA適合済み） |
| `--ev-blue-deep` | ヒーロー夜空グラデの下端 | **装飾専用。文字に使わない** |
| `--steel-hi/-mid/-lo` `--wordmark-grad` | ワードマークの鋼グラデ文字 | ダークの`--steel-lo`単色は大文字基準(3:1)のみ適合。グラデの一部としてのみ使う |
| `--surface-grad` | カード面の微グラデ（上端がわずかに明るい） | `background: var(--surface-grad)` で面に適用。罫線（`--line`）は従来どおり併用 |
| `--bg-grad` | 画面地の上下グラデ | ScreenLayout の地に適用 |
| `--cta-grad` | 主ボタンの金グラデ | `--on-gold` とのAA適合を両テーマで検証済み |
| `--glow-gold` / `--glow-raid` | 光暈（box-shadow値） | **適用は4箇所限定: 金CTA・ボスHPバー・ダメージトースト・リザルト数字** |
| `--hero-sky` / `--hero-line` | ヒーローカードの夜空グラデ・枠色 | **両テーマ共通**（ライトでも夜の車窓を維持する意匠判断。ライトブロックで上書きしない） |

### 3.2 ワードマーク・ロゴ運用

- アプリ内ヘッダーのワードマークは**画像でなくテキスト**: `font-family: var(--font-display)`＋イタリック風の`transform: skew(-6deg)`は不要（Chakra Petch自体に機械的な癖があるため）。`background: var(--wordmark-grad); -webkit-background-clip: text; background-clip: text; color: transparent;` で鋼グラデ文字にし、ダークのみ `filter: drop-shadow()` で電光青の淡い光を足す（モックアップ参照）。「BEB RAID」表記＋小さく「ビーブレイド」を併記。
- `logo.png`（フルエンブレム）の使い所: PWAスプラッシュ・アプリアイコン（現行どおり）・設定画面のAboutブロック・README。**ライトテーマ面には置かない**（07決定済み事項）。

### 3.3 ボス紋章コンポーネント（BossSigil）

`components/BossSigil.tsx` を新設。props: `seed: string`・`size: number`。実装要件:

- シードからのハッシュ（djb2等の単純なもので可）で 多角形の辺数（5〜8）・回転角・軌道環の数（1〜2）と破線パターン・核の半径 を決定的に導出する。**同一シード同一出力**（スナップショットでなく属性値のアサーションでテスト）。
- 色は `--raid` 基調＋`--ev-blue` の環。**必ずCSS変数参照**（`stroke="var(--raid)"`）でテーマ追従させる。
- `aria-hidden="true"`（装飾）。アニメーション無し。
- 討伐済み表現（紋章の割れ）は本計画のスコープ外（S5の演出強化時に追加）。

### 3.5 画像生成AI（codex等）に出すもの・出さないもの

| 対象 | 判断 | 理由 |
|---|---|---|
| キービジュアル（スプラッシュ・OGP・README用） | **生成する**（V-8。プロンプトは4節） | UI外の一枚絵はスタイル一貫性の問題が出ない。世界観の広報素材になる |
| ライト用単色ロゴ | 生成を試す（ベクター再作画が本命） | ラスター生成では小サイズ・単色の再現が不安定 |
| UIアイコン（モードタイル等） | **生成しない**（インラインSVGで自作） | 生成画像はアイコン間のスタイル一貫性が保てず、容量・テーマ追従でも不利 |
| ボス紋章 | **生成しない**（コード合成。07の6節の規定どおり） | 週次で無限に量産する前提のため |
| 背景テクスチャ | **生成しない**（CSSグラデで足りる） | 容量・バッテリーの原則維持 |

### 4.3 生成時の注意（人間向け）

- 色コードはプロンプト内の値（アプリのトークンと同値）を使う。生成結果の色が外れた場合は後段のトーンカーブ調整で寄せてよい。

- 権利: 生成物を public リポジトリに置くため、商用利用・再配布可能な生成サービス／プランで生成すること。生成サービス名・日付を `docs/design/` にメモとして残す。
