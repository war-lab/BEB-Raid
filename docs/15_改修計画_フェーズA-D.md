## 0. 実装セッションの共通ルール

1. まず `docs/STATUS.md` で現在地を確認し、本書の該当タスクシートだけを読んで着手する（他タスクの先取りをしない）。
2. 完了条件は build / test / lint / format の全通過＋シート記載の固有条件。実ブラウザ確認が可能な環境なら `npm run dev`＋Playwright系で操作確認する（不可能な場合はSTATUSに🟡で明記）。
3. dev へ直接コミット（運用特例の継続。STATUS.md 体制メモ参照）。コミットメッセージはプレフィックス付き日本語。
4. docs との矛盾を作らない。設計変更を伴う場合は該当 docs を同時更新し、docs に無い技術判断はコミットメッセージまたは `docs/adr/` に記録する。
5. **C-1〜C-4（スキーマ・platform・エンジンIF）に触れる変更は該当タスクシートに明記されている範囲のみ**。範囲外の契約変更が必要になったら停止して発起人に確認する。
6. 各タスク完了時に STATUS.md のタスク表（本書用に新設する「改修タスク状態」表）を更新する。
