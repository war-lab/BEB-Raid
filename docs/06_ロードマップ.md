# 06. ロードマップ

## 0. スコープ方針

- **M1は電車ソロのコアループだけを完成させる。** レイド・昼イベントはコンテンツ在庫と出題ロジックが固まってから。盛り上げ系を先行させると、盛り上がった後に「続ける理由」がなく失速する。
- 主役ユーザー（380→760）が**自分一人でも毎日使う状態**を最初のゴールにする。仲間はその上に乗せる。

- key単語システム（誤答→key語彙SRS→類題出題）

- コンテンツパイプラインCLI（LLM生成→TTS→パックビルド→Actions デプロイ）。**人手レビューはスプレッドシート/JSONL＋目視で行い、専用レビューUIはM2に回す**（M1の最大のボトルネックはレビュー工数。ツール整備より在庫作りを優先）

## 2. 意図的に見送るもの

| 項目 | 理由 |
|------|------|
| PDF自動取込 | 精度が安定せず工数対効果が悪い。LLM半自動変換＋人手確認で代替 |
| シャドーイング自動採点 | 実装コスト大・精度不安定。カラオケ式支援と録音セルフチェックで実用上足りる |
| 最初からのネイティブアプリ | PWAで検証してから。技術選定でネイティブ化路線は確保済み（05） |
| 全社・絶対スコアランキング | 心理的安全性を壊す。成長ランクとベストグロース賞で代替 |
| 常設サーバー（初版のASP.NET Core構成） | 静的+エッジ無料枠で全要件が賄えるため廃止 |
| Part7長文のバトル出題 | テンポが合わない。ソロ専用 |

## 3. 着手前の確認事項

1. **手持ちJSON/PDF素材の出所**（01のR-1）。市販教材由来なら取込まず、初期コンテンツはLLM生成に全振り。
2. **TTSの調達**: ✅ 解消（2026-07-13）。**Piper（ローカルTTS、MITライセンス）を採用**。無料の徹底（アカウント・カード登録不要、クラウド課金の仕組み自体が存在しない）を最優先し、Azure Speech（F0無料枠）・Google Cloud TTS等のクラウド案は見送った。ローカルビルド時生成（05のネイティブ化・ランタイム課金ゼロ方針）とも合致する。
3. **リポジトリをpublicにできるか**の最終確認（Pages無料運用の前提。privateだとPages有料＋アクセス制御なしなので旨味が薄い）。
4. 仲間の参加見込み人数と昼イベントの頻度（M3/M4の優先度に影響。当面自分一人ならM3を後ろへ倒してM2の質を上げる）。

## 4. 効果測定

- 実試験・IPテストのスコアを任意登録し、予測スコアとの乖離を記録→予測モデルの校正に使う。
- 追うKPI: **週あたり学習日数（最重要）**、電車セッション数/週、SRS消化率、レイド参加人数。スコアより先に継続が死ぬので、継続指標を最優先で監視する。
- TTS音声で訓練したリスニング力が本試験音声に転移しているかは、実試験スコアのL/R内訳と予測の乖離で監視する（TTSは弱形・脱落が実発話より明瞭に出る傾向があり、知覚訓練が本試験と乖離する可能性がある）。
