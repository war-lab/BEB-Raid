# 31. 敵対的検証棚卸し（2026-08-06）

## 1. 結論

9観点の敵対的検証を並行して実施し、所見99件を記録した。

最優先はレイドダメージの同期が本番で成立していない疑いである。基礎点は整数だが `solo` のモード係数0.5を掛けた値を丸めずに送るため、基礎点が奇数のときダメージが小数になる。サーバーは非整数を400で拒否し、クライアントは拒否されたバッチを削除しないため、`pendingSync` は以後排出されない。レート200〜900と難易度1〜5の全145通りのうち51通り（35.2%）が該当する。

次に、品質を保証しているのが仕組みではなく規律である点が挙がった。`main` のブランチ保護に必須ステータスチェックの設定が無く、`dev` は保護されていない。本番配信の `deploy.yml` はテストもlintも実行しない。テストファイルは型検査の対象外で、型エラーが11件残っている。カバレッジは計測手段自体が用意されていない。

バックアップJSONに共有APIのBearer資格情報である `deviceToken` が平文で含まれ、エクスポートUIに警告が無い。BYOK APIキーは正しく除外されているため、同性質の値だけが除外リストから漏れている。

Service Workerは `autoUpdate` かつ更新検知のコールバックを渡していないため、セッション中に無警告で `location.reload()` を実行する。[18_改修計画_表示更新とUX残課題](18_改修計画_表示更新とUX残課題.md) はこの挙動を「回避した」と記録しているが、実装は回避していない。

コンテンツでは、Part3/4の設問と解説が話者の性別を10箇所で取り違えている。Part2の150問はすべて直接疑問文で、本試験の25〜30%を占める平叙文・付加疑問・選択疑問が1問も無い。配信1735問のうち人手レビューの証跡があるのは読解238問（13.7%）に留まる。

反証も課した。`attempts` の追記のみ、著作権の分離、プライバシー境界の型による強制、ISO週計算、冪等送信の原子性は、いずれも実測で破れなかった。

### K-1 の機構

`basePoints` は `Math.round` を通した [40,130] の整数で、約半数が奇数になる。

`computeDamage` は `basePoints * coefficient` を返すだけで丸めを持たない。`damageConfig.json` の `solo` 係数は0.5なので、基礎点が奇数のとき結果は `X.5` になる。ゴースト週は `raid` 係数1.0でも防御倍率0.5を掛けるため同じく小数化する。

サーバーの `isDamageValue` は `Number.isInteger` を要求する。`isRaidSyncRequest` は `payloads.every(...)` で全件を検査するため、1件の小数が最大200件のバッチ全体を400にする。

`syncRaidDamage` の catch は `{ ok: false }` を返すだけで `pendingSync` を削除しない。滞留の掃除は成功レスポンス時にしか走らないため、先頭に小数レコードが1件入った時点でキューは流れなくなる。

ホームのクエストと単独モードのドリルはすべて `mode: 'solo'` である。レイド参加中のユーザーが通常のドリルで1問正解すれば、約3回に1回この経路に入る。

再現手順は付録B-1に置いた。

### K-1 を検出できなかった理由

両パッケージのテストが矛盾したまま、いずれも通っている。

`api/src/raidHandlers.test.ts:117` は `damage: 1.5` を不正値として400を期待する。一方 `app/src/engine/damage.test.ts` の入力は `80` と `50` だけで、0.5を掛けても整数にしかならない。

アプリ側の算出値をAPI側の検証器へ通す結合テストが存在しない。パッケージ境界に検査が無いことが、この不整合を成立させている。

### K-2 の機構

`exportAll` は `settings` ストアにのみ `EXPORT_EXCLUDED_KEYS` を適用し、`profile` は無加工で出力する。

`deviceToken` は識別子であると同時に `Authorization: Bearer` の値そのものである。サーバー側の `authenticateRequest` はKVに `member:<token>` が存在するかしか見ない。

漏洩方向では、バックアップファイルを入手した者が被害者名義でダメージを送信し、ゴースト記録を削除できる。招待コードは不要である。

奪取方向では、`importAll` が `profile` を `clear()` してから `bulkPut()` するため、細工したファイルを読み込ませるとその端末は攻撃者のトークンで動作する。以後の学習成果は攻撃者の貢献として集計される。

BYOK APIキーは `settings` の除外キーとして正しく扱われている。除外の対象がストア単位で `settings` に限定されていることが原因である。

### K-3 の機構

ビルド生成物の `dist/sw.js` に `self.skipWaiting(), e.clientsClaim()` が含まれ、バンドル側に `activated` イベントでの `window.location.reload()` がある。`main.tsx` は `registerSW({ immediate: true })` のみで `onNeedReload` を渡していないため、リロードは無条件に実行される。

解答のスナップショットは1問ごとに永続化されるため、失われるのは進行中の1問と画面の一時状態に留まる。ただしシャドーイングの周回数、イベントバトルのWebSocket接続、各画面のReact stateは復元されない。

[18_改修計画_表示更新とUX残課題](18_改修計画_表示更新とUX残課題.md) は「更新方式は現状維持（autoUpdate・次回起動時反映）。ドリル最中の自動reloadでセッション画面が飛ぶ逆リスクの方が大きいという判断」と記録している。実装と文書のどちらかが誤っており、現状は文書が誤っている。

### K-4・K-5 の共通点

いずれも `DrillScreen` には対処があり、他画面に無い。

`DrillScreen` はスキップ失敗時に `setSessionError` へ倒し、「中断ボタンすら無い白画面で固まる」理由をコメントに残している。`ReadingScreen` は同じ経路を `.catch(() => {})` で握り潰し、`sessionError` 状態自体を持たない。effectの依存が変わらないため再試行も起きない。

`BattleScreen` の「もう一度試す」は `setPhase('entry')` のみで、`answerRecords`・`finalized`・`answeredThisQuestion`・`currentQuestionRef` を初期化しない。前回バトルの誤答が新バトルの誤答数と復習IDに混ざり、未解答のまま切断していた場合は再参加後の最初の `questionOpen` で前回の問題に対する時間切れattemptが書かれる。`attempts` は追記のみなので取り消せない。

同型の実装が片方にだけ入っている状態は、レビューでも検出されにくい。改修時は対称性の確認を完了条件に含めるべきである。

### K-9・K-10 の実測値

`main` のブランチ保護のレスポンスに `required_status_checks` キーが存在しない。承認必要数は0、`enforce_admins` は無効である。`dev` は404（保護なし）で、rulesetsは空である。

### K-11・K-12 の機構

### K-15 の機構

### K-22 の位置づけ

`attempts` をアプリ内から消せないことは実測で確認した（13節）。しかし実際の消失モードはアプリ内経路ではない。

不変条件が守っているのはアプリ内の削除経路であり、二重化は完全に手動かつ無告知である。この非対称は明示しておく価値がある。

### K-24 の機構

### K-70 の位置づけ

ADR 0013はゴーストの防御倍率をプライバシー不変条件の例外とし、例外の成立条件として同意画面での3点明示を挙げている。

`DELETE /ghosts/own` が消すのはKVの `ghost:<token>` と当週DOの `defenseJson`・`ghostJson` である。撤回までに `GET /raid/current` を受け取った端末には、`raidState.defenseJson` として問題別の倍率表が IndexedDB にコピーされており、撤回では消えない。前週以前のDOも保持期間の間はこれらを保持する。

### K-93 の算術

### K-97 の解釈

`ghostBossSelection.ts:42` のフィルタは `format` のみを見て `part` を見ない。`GHOST_BOSS_ELIGIBLE_FORMATS` は `text_passage` を含み、呼び出し元はセッションを `mode: 'battle'` で開始する。配信中のPart7単一40問のうち難易度4以上が9問あり、母集団に実際に入る。
