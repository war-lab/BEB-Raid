# 27. 出題と回答のUXストレス点検（2026-07-30）

## 1. 結論

出題・回答フローを実装コードで点検し、学習者にストレスを与えうる箇所を38件検出した。

このうち3件は挙動そのものが壊れている疑いがある。シャドーイングの3秒戻しで周回が加算されて実施記録が付く件、音声のみモードで確定後に残秒表示が固着する件、診断と語彙SRSに連打防止がなく二重記録・カード飛ばしが起きる件である。

残る35件は動作としては仕様どおりだが、負荷が特定の場所に偏っている。誤タップ救済（ADR 0009）が2形式のみを対象とする一方、より不可逆な語彙仕分けのスワイプには救済がない。時間制限は聞き直しでも進み続け、時間切れは救済も統計上の区別もなくSRS復習デッキへ落ちる。初回診断は30問すべて正誤を返さない。

本書は所見の記録である。**改修計画は [28_改修計画_出題と回答のUXストレス](28_改修計画_出題と回答のUXストレス.md) が正本で、着手時はそちらを読む**。12節のJ-89〜J-97のうち、J-90・J-91・J-92・J-96・J-97は2026-07-30に発起人が承認した。残りの正文と追加のJ-98・J-99は28の3節にある。

## 3. 点検の範囲と方法

`packages/app/src` 配下の出題・回答に関わる画面・エンジン・サービスを読み、挙動を実装から確認した。対象はドリル（DrillScreen）・読解（ReadingScreen）・語彙SRS（VocabScreen）・シャドーイング（ShadowingScreen）・イベントバトル参加（BattleScreen）・初回診断（DiagnosticScreen）・出題選択エンジン（`engine/quickPack.ts`・`engine/srs.ts`・`engine/keyVocab.ts`・`engine/ratingDifficultyFilter.ts`）である。制限時間の一部は `packages/api/src/battleRoomDo.ts` にあるため併せて確認した。

実機・ブラウザでの動作確認は行っていない。所見はすべてコード読解に基づく。したがって4節の不具合の疑いは**未再現**であり、修正着手前に再現手順の確立が要る。

対応済みの課題は本書から除いた。具体的には [19_改修計画](19_改修計画_モード完走性とセッション導線.md) のT-118〜T-122、[18_改修計画](18_改修計画_表示更新とUX残課題.md) のT-103〜T-117、2026-07-29の出題・回答方式ブラッシュアップ4件（Part2音声のみモード・語彙リコールの提示順・当て勘と速度不足の可視化・誤タップの取り消し猶予）である。ただし対応の結果として残った副作用・未検証項目は所見として挙げた（S-8・S-11）。

コンテンツ側の出題品質（解説文の文体・類題在庫そのものの不足）は本書の対象外とする。14の3.1〜3.6と15のT-80〜T-86が扱う領域である。

タップ目標サイズは点検したが所見に挙げていない。全解答ボタンで48px以上が守られている（`components.css:7,38-39`・`tokens.css:109-110`）。誤タップ起因の負荷はサイズではなく、取り消し可否と確認の有無という時間軸の設計に集まっている。

## 4. 不具合の疑い（S-1〜S-3）

| ID | 症状 | 該当箇所 |
|----|------|----------|
| S-1 | シャドーイングで3秒戻し・文タップをすると周回が加算され、練習していないのに3周完了扱いになる | `ShadowingScreen.tsx:130-182`・`WebAudioPlayer.ts:91-121,146` |
| S-2 | 音声のみモードで再生中に解答すると、確定後もヘッダに残秒が固着する | `DrillScreen.tsx:662-670,844-850` |
| S-3 | 初回診断と語彙SRSに連打防止がなく、二重記録またはカード飛ばしが起きる | `DiagnosticScreen.tsx:351-406,450-459`・`VocabScreen.tsx:247-280` |

### S-1 の機構

**2026-07-30 訂正**: 当初は原因を `WebAudioPlayer` の実装の誤りと記述したが、不正確だった。以下は訂正後の記述である。

`AudioPlayer.play()` のインターフェース契約は「再生完了（または stop）で resolve する」と定めている（`platform/audio/AudioPlayer.ts`）。`playSequence` も「途中で stop された場合は残りを再生せず resolve する」と明記している。`WebAudioPlayer` は契約どおりに動いており、実装の誤りではない。

誤りは契約と呼び出し側の解釈の不一致にある。`handlePlay` は `await audioPlayer.play(...)` の解決後に `handlePlaybackEnded()` を呼び `laps` を1加算するが、契約が完走と中断を区別していないため、呼び出し側には区別する手段がない。

`WebAudioPlayer.startSequence` は冒頭で `this.stop()` を呼び、`stop()` は保持している `pendingResolve` を即座に解決する。再生中に「3秒戻し」や文タップで新しい再生を始めると、中断された前の `play()` の await が解決し、周回が加算される。

修正はインターフェースの契約変更（[28](28_改修計画_出題と回答のUXストレス.md) のT-155）が起点になる。

`COMPLETION_LAPS = 3` のため、3秒戻しを3回押すだけで完了条件に達する。`recordAttempt` で `shadow:<id>` の実施ログが記録され、表示も「次へ」に切り替わる。進捗表示「{laps}/3周」が練習の実態と乖離する。

### S-2 の機構

`handleSelect` が `audioPlayer.stop()` を呼ぶと、`WebAudioPlayer.stop()` が `pendingResolve` を即解決する。これにより中断されていた `handlePlayStart` 内の `await play()` が再開し、後続の `if (isAudioQa && !result) setRemainingSec(...)` を実行する。

この `result` は再生開始時のレンダーで捕捉されたクロージャ値（`null`）であり、解答済みを検出できない。コード上のコメントはこの経路を防ぐ意図を宣言しているが、機能していない。

結果として、解答済みなのにヘッダに「6」等が表示されたまま止まる。`isCountingDown` は false なので減少はしない。学習者は時間切れだったのか判別できない。

### S-3 の機構

診断の `handleSelect` はボタンを `disabled` にせず、解答済みフラグも持たない。同一の `question` と `turn` に対して2回発火すると、`recordAttempt` が2件記録され、`updateDiagnosticRating` も2回走る。`turn` は同じ値から計算されるため進行は1問分にとどまり、レートだけが二重に動く。診断レートは以降のすべての出題難易度に影響する。

語彙SRSの `handleGrade` も `disabled` 制御を持たず、`await recordAnswerPipeline(...)` の後に `setReviewIndex((i) => i + 1)` を実行する。連打すると更新関数が2回走り index が2進む。SRS間隔が更新されないカードが1枚、無言でスキップされる。

## 5. 所見: 不可逆操作の保護（S-4〜S-8）

ADR 0009 は誤タップ救済として400msの取り消し猶予を導入したが、対象は `UNDO_TARGET_FORMATS`（text_blank・audio_qa）に限られる。より不可逆な操作に救済がない状態が残っている。

| S-5 | 語彙カードの自己評価が即次カードへ進み、戻る手段がない | `DrillScreen.tsx:104-106,1028-1064,1118-1188` |
| S-6 | 「ここで終了して結果を見る」が「次へ」の直下にあり、確認なしでセッションを打ち切る | `DrillScreen.tsx:1441-1453` |
| S-7 | 画面最上部の「中断」が確認なしでホームへ遷移する | `DrillScreen.tsx:1071-1073`・`ReadingScreen.tsx:230-232`・`VocabScreen.tsx:327-330` |

S-4 の不可逆性が最も高い。横80px以上のスワイプで `markVocabKnown` が卒業済みSRSカードを作成し、その語は仕分け候補からも復習キューからも外れる。取り消しはない。ドリル側に400msの猶予を入れた一方で、この操作には保護がない。

S-5 は `handleVocabGrade` が成功後すぐ `advanceToNext()` を呼ぶ設計による（コメントに「正誤確認のポーズを挟まず」と明記）。フレーズや正解を読む前に押すとカードが消え、vocab_card は取り消し対象外のため戻れない。操作ゾーンに評価3段階・「フレーズを再生」・「わからない」が縦積みされており、誤タップの確率も低くない。

S-8 の空白待ちは猶予導入の副作用である。`pending !== null` の間は解説カード・「次へ」・途中終了導線を描画せず、高さ予約の空スロット（`min-height: 48px`）だけが出る。対象形式が2つのため、形式によってテンポが不統一になる。ADR 0009 自身が400msを実機未検証としてドッグフードでの調整を前提にしている（ADR 0009:97-98）。

## 6. 所見: 時間圧（S-9〜S-13）

| ID | 症状 | 該当箇所 |
|----|------|----------|
| S-9 | 15秒タイマーが「もう一度再生」中も止まらず、聞き直すほど解答時間が減る | `DrillScreen.tsx:395-404,878-885,1271-1275` |
| S-10 | 時間切れは自動で誤答確定・取り消し対象外で、当て勘と区別なくSRS復習デッキへ落ちる | `DrillScreen.tsx:427-434,590`・`attempts.ts:29-42`・`keyVocab.ts:41-68` |

| S-12 | 先読み時間（15/15/10秒）は延長できず、0で強制的に再生が始まる | `DrillScreen.tsx:146,416-423,1258-1269,1345` |

S-9 の機構は `isCountingDown = isAudioQa && playState === 'played' && !result` である。リプレイは `playState` を変えないため、リプレイ中もカウントダウンが進む。聞き取れずに聞き直す行為が解答時間の減少というペナルティになる。

S-10 は環境要因の失点が学習データに残る問題である。電車での接触・通知の割り込みで15秒を消費すると、`finalizeAnswer(null, false, true)` が誤答を確定する。`undoable` は `!isTimeout` 条件のため取り消せない。`processWrongAnswer` は時間切れも当て勘も区別せず復習デッキへ登録するため、実力とは無関係な失点が復習キューを膨らませる。

S-12 は02の99行が定める「型の強制」に沿った設計であり、短縮（「もう再生する」）はできても延長はできない。Part3/4の3問分の設問と選択肢を10〜15秒で読み切れない学習者に逃げ道がない点を所見として挙げる。

S-13 は制限時間ではないため自動確定はしない。「目安1問/分」の表示が超過後も「経過180秒」と出続けるため、機能的な影響なしに心理的な圧だけが増える。

## 7. 所見: 音声の挙動（S-14〜S-17）

| ID | 症状 | 該当箇所 |
|----|------|----------|
| S-14 | 2問目以降は問題切替と同時に自動再生され、opt-outも停止ボタンもない | `DrillScreen.tsx:213,386-391,842` |
| S-15 | 再生中は問題文・設問文が「再生中…」に置き換わる | `DrillScreen.tsx:1490-1512` |
| S-16 | 語彙仕分けもカード表示と同時に自動再生し、画面内に停止手段がない | `VocabScreen.tsx:74,115,164-170` |

S-14 の自動再生は18のT-110で意図的に導入した挙動である。所見は挙動そのものではなく、opt-outの不在にある。`hasPlayedOnceRef` が立つと `question?.id` の変化で `handlePlayStart()` が即実行され、心の準備・音量調整・イヤホンの装着直しの間がない。`audioPlayer.stop()` はUIに露出しておらず、`settingsKeys.ts` に該当キーもない。

S-16 は公共の場での事故につながる。`inTriagePhase` かつ `autoPlay`（イヤホンなしモードOFF、既定）でカードが変わるたびに再生する。20語を連続でスワイプすると音声が次々に鳴って途中で切れる。イヤホンなしモードのトグルはこの画面になく、設定画面へ移動しないと切り替えられない。

S-17 は単独では軽微だが、S-1 と連動する。止める手段がないため他の再生で上書きすることになり、それが周回の誤カウントを起こす。

| S-35 | バトルの制限30秒が問題種別に関係なく一律で、事前告知もない | `battleRoomDo.ts:29,288-297`・`BattleScreen.tsx:146-152,339-343` |
| S-36 | バトルは解説が出ず、未解答は記録にも残らない | `BattleScreen.tsx:227-253,344-352,423` |
| S-37 | シャドーイングで素材を移動すると周回が0に戻る | `ShadowingScreen.tsx:184-207,249-252` |
| S-38 | 破棄確認が `window.confirm` で、「続きから再開」を同じ場で選べない | `HomeScreen.tsx:57-59,336-342`・`RaidScreen.tsx:320-337` |

S-31 は19のT-122でドリルに追加した途中終了導線が読解へ未適用であることによる。`handleNext` は `answers.size >= subQuestions.length` を満たすまで `findNextUnanswered` で同一パッセージ内を巡回する。抜ける手段は「中断」（ホームへ）だけで、リザルトを見られない。

S-32 は通常出題からは `isReadingAllocatable` で除外されている。ただしSRS復習item経由の `srsItem` は `isServable` のみで判定するため混入経路が残る。相互参照型の設問が出た場合、2通目を読めないまま解答不能になる。

S-34 は投影を前提とした設計の穴である。参加者画面は `currentQuestion.question` を描画するが、audio_qa の `question` は未定義であり、ホスト投影側の `projectedQuestionText` に相当する補完がない。参加者端末では音声も再生しない。投影が見えない位置の参加者は、空白と選択肢だけを見ながら30秒を消費する。

S-36 はソロ学習との不整合を含む。解答後に表示されるのは選択肢の色と「獲得点: N点」のみで、`ExplanationCard` は使っていない。締切までに解答しなかった場合は `handleAnswer` が呼ばれず、`attempts` に何も残らない。ソロ側が `isTimeout` として記録・可視化しているのに対し、バトルの時間切れは統計にも復習にも反映されない。

S-38 の `confirmDiscardMessage(remaining)` は19のT-122で残り問数入りに具体化した。残る所見は選択肢の構造である。ネイティブダイアログのYes/Noのみでは、「続きから再開する」を選ぶにはホームへ戻って別のボタンを探す必要がある。

## 11. 学習者が調整できない固定値

`services/settingsKeys.ts` にキーが存在するのは、イヤホンなしモード・テーマ・文字サイズ・BYOK・ハプティクス・誤タップ取り消しのON/OFF・レイド同期・questionStats・クエスト長・単独モード問数である。

以下はコード定数で固定されており、個人差（読速・リスニング力・端末の反応速度）を吸収する手段がない。

| 固定値 | 場所 |
|---|---|
| audio_qa 解答15秒 | `DrillScreen.tsx:79` |
| 音声のみモード 解答6秒 | `DrillScreen.tsx:87` |
| 取り消し猶予 400ms | `DrillScreen.tsx:96` |
| 冒頭だけ再生 2500ms | `DrillScreen.tsx:140` |
| 先読み 15/15/10秒 | `DrillScreen.tsx:146` |
| 2問目以降の自動再生 ON | `DrillScreen.tsx:213,386-391` |
| シャドーイング 完了3周・3秒戻し | `ShadowingScreen.tsx:34,36` |
| 仕分け区切り 20語 | `VocabScreen.tsx:49` |
| スワイプ閾値 80px | `SwipeCard.tsx:12` |
| バトル1問 30秒 | `battleRoomDo.ts:29` |
| SRS 新規20/日・滞留停止16件 | `srs.ts:29-32` |
| SRS 間隔 1/3/7/14/30/60日 | `srs.ts:16` |
| 当て勘判定 2秒 | `services/attempts.ts:10` |

すべてを設定可能にすべきという主張ではない。「型の強制」を意図した値（先読み秒数）と、実測前の暫定値（6秒・400ms）と、設計思想に属する値（SRS間隔）が同じ扱いで固定されている点が所見である。

## 12. 要判断事項（J-89〜J-97）

4節の3件（S-1〜S-3）は挙動の不具合であり、判断を要さず修正できる。ただし再現手順の確立が先に要る。

以下は設計正本またはADRの改訂を伴うため、発起人の判断が要る。

| ID | 論点 | 関係する所見 | 影響する正本 |
|----|------|------------|------------|
| J-89 | 誤タップ救済の対象範囲を語彙仕分け・語彙カードへ広げるか。猶予400msを実測に基づき変えるか | S-4・S-5・S-8 | ADR 0009 |
| J-90 | 解答制限時間を学習者が変えられるようにするか | S-11・11節 | 02の69-75行 |
| J-91 | リプレイ中はタイマーを止めるか | S-9 | 02の69-75行 |
| J-92 | 時間切れを当て勘と同様に区別して扱い、SRS登録の対象から外すか | S-10 | 03のSRS節 |
| J-93 | 2問目以降の自動再生にopt-outを設けるか | S-14 | 18のT-110の意図 |
| J-94 | 直近に解答した問題を出題候補から外す仕組みを入れるか | S-18 | 03の出題選択 |
| J-95 | 初回診断に正誤フィードバックを追加するか。測定精度への影響をどう見るか | S-25 | 03の診断・レーティング |
| J-96 | 復習キューに区切りを設けるか（19の6節で見送った判断の再検討） | S-21 | 19の6節 |
| J-97 | バトルの退出導線と一律30秒を見直すか | S-33・S-35 | 22のWebSocketプロトコル |

J-90 と J-91 は実測が前提になる。音声のみモードの6秒と取り消し猶予の400msはいずれも推定値であり（ADR 0009:97-98、`DrillScreen.tsx:87` のコメント）、実機の親指操作での妥当性が未確認である。判断の前にドッグフードでの計測を置くのが順序として妥当と考える。

J-92 は影響範囲が広い。時間切れをSRS登録から外すと、聞き取れずに時間を使い切った問題が復習に出なくなる。環境要因の失点と実力による失点を実装上区別できない以上、どちらの誤りを許容するかの判断になる。
