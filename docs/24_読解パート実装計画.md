### 2.1 ブランチ運用

- `task/T-xxx-説明` ブランチで作業し、dev への **PR（ドラフト作成→CI通過→マージ）** で入れる。dev直コミットはしない。

### 2.2 新規依存の方針

- **新規依存ゼロ**を原則とする。読解はテキストのみで、音声・キャッシュの新規抽象を要しない。必要になったら停止して人間に確認する。

### 2.3 不変条件（毎タスクで回帰確認する）

1. **オフライン正常系**: 解答記録は IndexedDB へ即時保存（04）。読解も通常の attempt として記録する。
2. **attempts追記のみ**（削除APIを作らない）。
3. **プライバシー境界**: 読解の questionStats も既存の匿名集計（deviceTokenと結合しない）に乗せるだけ。新たな個人紐づき送信を作らない（04）。
4. **縮退設計**: 共有API無効時にソロ学習の動作・表示が変わらないこと。読解は共有APIに依存しない機能なので、API無効でも完全に動くこと。
5. **platform層に触れない**: 読解はテキストのみのため、音声再生・キャッシュ抽象（platform/）を変更しない。

### 2.4 停止規則

- シート・3節・ADR 0006 に無い設計判断が必要になったら停止する。
- 既存の audio_set / SRS / レート / 中断復帰 / タグ統計の再利用で不整合が出たら、勝手に回避せず停止して報告する。
- 完了条件を1つでも満たせない場合、条件を緩めず停止して報告する。

## 3. 事前決定事項（正文）

数値・命名はすべて本節が正本（変更する場合は本節を直す）。

### 3.1 スキーマ（ADR 0006 判断3）

`packages/shared-schema/src/types.ts` に以下を追加する。

```ts
/** 読解の刺激文書。Part7複数パッセージは配列長2〜3 */
export interface Passage {
  id: string
  /** email | notice | article | chat | form | advertisement 等。表示ラベルと出題文脈 */
  kind: string
  /** 本文。Part6は空所マーカー [[1]]…[[4]] を埋め込む */
  text: string
}
```

`Question` に `passages?: Passage[] | null` を追加する（`text_passage` 用）。

- 設問は既存の `subQuestions: SubQuestion[]` を再利用する（音声セットと同一構造）。
- **Part6**: `passages` 1件、`text` に `[[1]]…[[4]]` を4個埋め込む。`subQuestions` は4問で、n番目が `[[n+1]]`（1起点マーカー）に対応する。選択肢4つ。文挿入問題もこの枠（選択肢が挿入文）で表現する。
- **Part7単一**: `passages` 1件、`subQuestions` 2〜4問。
- **Part7複数**: `passages` 2〜3件、`subQuestions` 5問。相互参照が必要な設問には `subQuestion` にタグ（例: `cross-reference`）を付ける。
- 追加フィールドは後方互換のため `SCHEMA_VERSION` は据え置く（2のまま）。
- `validate.ts` に `text_passage` の必須検証を追加する: `part` が 6 または 7、`passages.length >= 1`、`subQuestions.length >= 1`、`keyVocab.length >= 1`（vocab_card以外の既存規約）、Part6 は空所マーカー数と `subQuestions.length` が一致すること。

### 3.2 採点（ADR 0006 判断4）

- 読解は `computeSetResult`（2/3ルール）を**使わない**。各 subQuestion を独立した採点対象とし、1問ごとに正誤を記録・レート更新する。
- レート更新対象: 読解の全 subQuestion を **Rセクションレート**に反映する（`engine/rating.ts` の既存Elo。L/R区分はRとして数える）。SRS復習・語彙カードがレート対象外なのは従来どおり。

### 3.3 セッション統合（ADR 0006 判断2）

`engine/quickPack.ts` / `engine/curriculum.ts` の配分に組み込む。

| パック | 読解 |
|--------|------|
| 3分 | なし（SRS復習のみ。現状維持） |
| 7分 | Part6 ＋ Part7単一を弱点配分に追加 |
| 15分 | ＋ Part7単一を厚めに。複数パッセージは入れない |
| 「じっくり読解」モード（新規） | Part7複数パッセージ専用（着席・自宅想定）。1〜2セットを通しで。時間目安を提示 |

フェーズ配分（03の1.2）への反映:

- P1（〜550）: Part6を少量導入（Part5文法の延長）。Part7複数は出さない。
- P2（550〜650）: Part7単一を本格投入（既存「Part7シングル15%」枠に対応）。
- P3（650〜）: 「じっくり読解」でPart7複数（既存「Part7マルチ30%」枠に対応）。

### 3.4 学習ロジック統合（ADR 0006 判断6・7）

- **弱点タグ**: 読解用の解法タグ（先読み/スキャン/パラフレーズ照合/相互参照/推論/語彙推測）を `tagStats` の集計対象に含める。既存のタグ体系（03の7.1「解法」分類）に乗せる。正答率60%未満で弱点判定・出題重み増（既存ロジックを流用）。
- **SRS再出題**: 本文まるごとの再出題はしない。誤答→keyVocab を SRS へ、弱点タグの重みを増やす（既存の 03の3.2 循環に接続）。再挑戦は同一タグ・keyVocab の別パッセージ・別Part5類題で行う。
- **noEarphoneFilter**: 読解コンテンツ投入後、`engine/noEarphoneFilter.ts` がリスニングを text_passage/text_blank に差し替える設計が本来どおり機能することを確認する（現状は text_passage の実体が無く text_blank にしか差し替わっていない）。

### 3.5 UI（ADR 0006 判断2）

- **新規 `screens/ReadingScreen.tsx`** を作る（DrillScreen に分岐追加ではなく専用画面。本文＋設問の2ペインが既存4択UIと別レイアウトのため）。
- 単一パッセージ: 上に本文（スクロール可）、下に設問＋選択肢。片手UIの下半分に解答ボタンを置く既存規約（02の2.2）を維持。
- 複数パッセージ: 本文をタブ切替（文書1/文書2/文書3）。相互参照の存在を示唆しすぎない範囲で表示。
- Part6: 本文中の空所を `___(1)___` 形式で表示し、該当設問へジャンプ。選択後に本文の空所へ反映。
- **中断復帰**: 既存のセッション中断復帰（append-only attempts・activeSession）に乗せ、1問解答ごとに保存する既存方式を使う。セット途中の離脱でも復帰可能にする。
- **ペース表示**: リスニングの自動誤答タイマー（15秒）は付けない。目標ペースの目安（本試験RCは約1分/問）を柔らかく提示する。時間切れで解き切れない層の底上げが目的で、速答を煽るものにしない。

### 3.6 コンテンツと初期在庫（ADR 0006 判断5）

- `packages/cli` に読解パック生成を追加する。本文＋設問の整合（複数パッセージで参照先が実在するか、Part6のマーカー数と設問数の一致）を機械検証する。
- **読解は人手レビュー必須ゲートを最初から有効化**する。AIクロスレビューのみでの配信を認めない。`origin` にレビュー実施状況を正直に記録する。
- 初期在庫の目標量（暫定・ドッグフード実測で調整）: **Part6 30セット（120問）／Part7単一 40セット（約120問）／Part7複数 15セット（75問）**。MVP（フェーズR-1）ではPart6＋Part7単一を先行し、複数はR-2で追加する。
