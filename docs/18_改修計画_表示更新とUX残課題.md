## 3. 事前決定事項（J-51〜J-56の正文）

### 3.1 表示更新の基盤方式（J-51）

- **バックグラウンド同期の完了を画面へ通知する仕組みとして、Zustandの小ストア `raidSyncStore` を新設する**（T-103が実装の正本）。フィールドは `syncCount: number`（同期試行が完了するたびに+1。成否問わず）・`lastFailed: boolean`・`lastUnauthorized: boolean`。
- 既存の `services/raidSync.ts` のモジュールスコープフラグ（`isLastRaidSyncFailed()`/`isLastRaidSyncUnauthorized()`）は**このストアへ移設して廃止**する。移行期の二重管理はしない（1タスク内で置換完了させる）。
- 画面は `useRaidSyncStore((s) => s.syncCount)` を購読し、useEffectの依存に加えることで「同期完了→DB再読込」を実現する。Dexieのライブクエリ系ライブラリは導入しない（依存ゼロ原則。20人規模・画面数個の用途にはカウンタ通知で十分）。
- Service Workerの更新方式は**現状維持**（autoUpdate・次回起動時反映。定期 `registration.update()` は導入しない）。ドリル最中の自動reloadでセッション画面が飛ぶ逆リスクの方が大きいという判断。

### 3.2 リザルト集計の仕様（J-52）

- ResultScreenの集計（正解数・問題リスト）は**中断・再開を跨いだセッション全体**を表示する。根拠: 「20問中17問解答→中断→再開して3問」のとき「正解2/3」と表示される現行挙動は、ユーザーには集計欠落に見える（2026-07-18のPlaywright検証で観測）。
- 実装方式: attemptsストアから当該セッションの `sessionId` で読み直す（attemptsに `sessionId` が無い場合はスナップショットの `items` のquestionId集合×セッション開始時刻以降で近似する——シートT-109の調査手順に従い、無理に新カラムを増やす前に停止して確認）。

### 3.3 リスニングの再生開始（J-53）

- **セッション内で一度ユーザージェスチャー起点の再生に成功したら、以降の問題は自動再生する**（毎問「タップして開始」を要求しない）。自動再生が拒否された場合（iOSの制限等）はその問題から従来のタップ開始表示へフォールバックする。
- 開始ボタンのラベルは「タップして開始」→「音声を再生」に変更（セッション開始と紛らわしいため）。

### 3.4 時間チップの扱い（J-54）

- ホームの3分/7分/15分チップは**「今日のクエスト」専用であることをUIで明示**する（チップ群をクエストボタンに隣接・グループ化し、ラベル「クエストの長さ」を付す）。
- 選択値は settings に保存し、画面遷移・再起動を跨いで維持する（現行は遷移で7分に戻る）。
- Part2瞬発等の他モードには作用しない（従来どおり）。作用させる拡張はM4以降。

### 3.5 画面遷移とブラウザ履歴（J-55）

- **ルーターは導入しない**（13の2節の見送り事項を維持）。History APIの最小統合のみ行う: 画面遷移時に `history.pushState({ screen }, ...)` を積み、`popstate` でZustandの `navigate()` を呼ぶ。
- ドリル進行中のブラウザバックは、既存の中断確認（confirm）と整合させる: popstateでは確認なしで中断扱い（activeSessionは保存済みのため「続きから再開」で復帰できる。データは失われない）。
- スタンドアロンPWA（Android戻るジェスチャー）で「アプリ即終了」にならないことが受け入れ基準。

### 3.6 スキップの可視化（J-56）

- DrillScreenが問題を表示できずスキップする（questionId未解決・描画不能format）とき、**画面内の非モーダル通知**（次の問題の上部に「表示できない問題を1件スキップしました」を数秒表示、または問題カード上部の常設1行）を出し、**ResultScreenに「表示できなかった問題: N件」の行**を追加する。
- スキップ件数はセッションスナップショットに保持せず、DrillScreenのローカルstate＋ResultScreenへのストア渡しで実装する（スキーマ変更をしない。アプリ再起動を跨ぐ持続は不要）。

## 5. タスクシート

### T-103 レイド同期状態のストア化と画面追従 🟢

- **背景**: 起動時（App.tsx）・セッション完了時（ResultScreen）のバックグラウンド `syncRaidDamage` がDBのraidStateを書き換えても、表示中のHomeScreen/RaidScreenへ通知する仕組みがなく、HPバー・「最終同期」・週替わり後の表示が古いまま残る（毎起動でraceを踏む）。同期失敗の `is-stale` 強調も、モジュールスコープフラグをレンダー時に読むだけのため変化に追従しない。
- **変更ファイル**: `store/`（`raidSyncStore.ts` 新設）・`services/raidSync.ts`・`services/questionStats.ts`（トリガー共有部があれば）・`screens/HomeScreen.tsx`・`screens/RaidScreen.tsx`・`App.tsx`・各テスト。
- **実装指示**:
  1. 3.1節のとおり `raidSyncStore`（syncCount・lastFailed・lastUnauthorized）を新設。`syncRaidDamage` の完了処理（成功・失敗・401の各経路）でストアを更新する。
  2. `isLastRaidSyncFailed()`/`isLastRaidSyncUnauthorized()`/`resetRaidSyncFlagsForTest()` をストア参照に置換し、モジュールスコープフラグを削除する（参照元をgrepで全数確認: HomeScreen・RaidScreen・テスト）。
  3. HomeScreen/RaidScreenのraidState読込effectの依存に `syncCount` を加え、同期完了で再読込されるようにする。`is-stale` 強調はストア購読で自動追従になる。
- **完了条件**: (a) 新規テスト「起動時同期の完了後にHomeScreenのHPバー・最終同期表示が更新される」「同期失敗でis-stale強調が付き、次の成功で消える」。(b) 旧フラグ関数がコードベースから消えている。(c) 既存のHome/Raid/raidSyncテスト全通過。(d) 2.4節の全体検証。

### T-104 手動同期の部分失敗による表示矛盾の解消 🟢

- **背景**: RaidScreenの「今すぐ同期」は syncDamage成功→fetchCurrentBoss で画面を更新するが、後者だけ失敗すると「最終同期: たった今」（raidState由来）とボスHP・貢献一覧（currentBoss由来）が矛盾したまま表示され、エラーも出ない。「同期したのにダメージが反映されない」という見え方になる。
- **変更ファイル**: `services/raidSync.ts`・`screens/RaidScreen.tsx`・各テスト。
- **実装指示**: `syncRaidDamage` の戻り値を `boolean` から `{ ok: boolean; boss?: RaidBossState }`（レスポンスのbossを含む）に変更し、RaidScreenは同期成功時にこのbossで `currentBoss` を直接更新する（追加のfetchCurrentBossを不要にする。バッジ再取得は従来どおり）。戻り値変更の影響元（App.tsx・ResultScreen.tsxの呼び出しは戻り値未使用のはず）をgrepで全数確認する。
- **完了条件**: 新規テスト「同期成功時、追加fetchなしでボス表示が更新される」。既存の手動同期テスト・isLastRaidSyncUnauthorized系テストの回帰。2.4節の全体検証。

### T-105 時刻追従（60秒tick・日付跨ぎ再読込） 🟢

- **背景**: (a) 「最終同期: たった今」がレンダー時計算のみで、画面を開いたまま30分経っても変わらない。(b) レイド終了時刻（endAt）を画面表示中に跨いでも `raidEnded` が再評価されず、「レイドに挑む」が押せたまま（PR #26で入れた終了ボス無効化が時間経過に対して効かない）。(c) ホームを開いたまま0時を跨ぐ・PWAをバックグラウンドから翌日復帰すると、ストリーク・SRS期限バッジ・ヒートマップが前日値のまま（visibilitychange購読が皆無）。
- **変更ファイル**: `screens/HomeScreen.tsx`・`screens/RaidScreen.tsx`・各テスト。
- **実装指示**:
  1. 両画面に60秒間隔の `setInterval` で `nowMs` stateを進めるeffectを追加（レイド表示要素があるときのみ起動。クリーンアップ必須）。相対時刻・remainingDays・raidEndedの計算をこのstate基準に変える。
  2. HomeScreenに `document.visibilitychange`（visibleへの復帰時）のeffectを追加し、読込時の `toDateString` と現在が異なる場合にload()を再実行する。
- **完了条件**: 新規テスト「vi.useFakeTimersで60秒進めると相対時刻・raidEndedが更新される」「visibilitychangeで日付が変わっていたら再読込される」。tickがオフライン・API未設定でも例外を出さないこと（2.4節の不変条件1・2）。

### T-106 バックアップインポート後の設定画面再読込 🟢

- **背景**: SettingsScreenはインポート成功後に自画面のstateを再読込せず、全トグル・表示名・テーマ/文字サイズのラジオがインポート前の値のまま表示される。**このまま続けてトグルを操作すると「古い表示の反転値」でDBを上書きし、復元したてのデータを壊す**（表示バグではなくデータ破壊経路）。テーマ・文字サイズもDB値と画面適用が食い違う。
- **変更ファイル**: `screens/SettingsScreen.tsx`・テスト。
- **実装指示**: 初期読込effect内の処理を `load()` 関数として切り出し、`importAll` 成功後に再実行する。あわせてインポート後に `setTheme`/`setFontSizeScale` をDBの新値で再適用し、App側のテーマstateとずれないことを確認する（App.tsxのthemePreference連携がpropsコールバック経由なら呼び出す。実装を読んで確認し、経路が無ければ停止せずApp.tsxへの通知コールバック追加まで本タスクに含める）。
- **完了条件**: 新規テスト「インポート後、トグル・表示名・テーマ選択がインポートした値で表示される」「インポート直後のトグル操作が新値基準で書き込まれる」。2.4節の全体検証。

### T-109 リザルト集計をセッション全体に 🟡

- **背景**: 中断→再開したセッションのリザルトが再開後の解答分のみの集計になる（20問中17問→中断→再開3問で「正解2/3」）。J-52でセッション全体の集計を表示すると決定済み。
- **変更ファイル**: `screens/ResultScreen.tsx`・`services/`（集計関数）・各テスト。
- **実装指示**: まずattemptsのレコード構造を確認し、当該セッションの全attemptsを特定できるキー（sessionId相当）の有無を調査する。①キーがあればそれで読み直す。②無ければスナップショットのitems（questionId列）×セッション開始時刻以降のattemptsで近似する。**①②のどちらも成立しない場合はDBスキーマ変更に踏み込まず停止して報告**（スキーマ変更は共有面のため単独PR判断が要る）。レート変動・獲得ポイントの表示は現行どおり（今回セッション分）でよく、正解数と問題リストのみ全体化する。人間チェックポイント: 集計定義の変更なのでPR説明に前後の画面例を記載する。
- **完了条件**: 新規テスト「中断→再開→完了で、リザルトが全解答分の集計を表示する」。既存リザルトテストの回帰。

### T-110 リスニングの自動再生 🟢

- **背景**: リスニング系（Part2・dictation・audio_set）は毎問「タップして開始」が必要で、20問セッションで20回の余計なタップになる。ラベルもセッション開始と紛らわしい。
- **変更ファイル**: `screens/DrillScreen.tsx`・各テスト。
- **実装指示**: 3.3節（J-53）のとおり。セッション内で初回の再生成功を記録し、以降の問題はマウント時に自動再生を試みる。`audioPlayer.play()` が拒否されたら（unlock切れ・iOS制限）従来のタップ開始UIへフォールバックする（PR #26でWebAudioPlayerのplay拒否はrejectされるようになっているので、catchで拾える）。開始ボタンのラベルを「音声を再生」に変更。vocab_cardの既存自動再生との整合（二重再生しないこと。WebAudioPlayerの世代トークンで守られているが、テストで確認）。

### T-114 History API最小統合 🟡

- **背景**: ルーターレスSPAでブラウザ履歴と連動しておらず、Androidの戻るジェスチャー／ブラウザバックがアプリ終了相当になる。レイド登録・シャドーイング等の画面はPR #26で「ホームへ」導線を足したが、OSの戻る操作には依然対応していない。

- **完了条件**: 新規テスト「navigateで履歴が積まれ、popstateで前画面へ戻る」「ドリル中のpopで中断→続きから再開できる」。人間チェックポイント: 実機（Android実機またはエミュレータ）でのジェスチャー確認はH扱いでPRに残す。
