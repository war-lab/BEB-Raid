# リリースノート 2026-08-13（dev → main）

前回の main 反映以降に dev へ入った 192 コミットをまとめる。変更規模は 1150 ファイル・+50432/-17260 行で、うち 756 ファイルが音声（mp3）の追加・差し替えである。

このリリースは**本番の共有APIへ自動デプロイされる**（`packages/api` を含むため。docs/17 3.10節）。反映前に「本番へ出る変更」節を確認すること。

## 結論

3つの棚卸しの改修がまとまって入る。

1. **敵対的検証（docs/31・32）のウェーブ0〜9・92タスク**。本番で機能が損なわれていた欠陥8件を含む
2. **完了条件が未達だった7タスクの是正**。数値で書かれた条件を実測したところ満たしていなかったもの
3. **AIクロスレビューの適用範囲拡大と、読解フェーズR-2の配信開始**

学習者から見える一番大きな変化は、**問題数が 1467 → 1546 問、配信パックが 20 → 24 パックに増える**ことと、**週次ボスが毎週きちんと出るようになる**ことである。

## 本番へ出る変更（要注意）

| 変更 | 影響 |
|---|---|
| cron式を `0 0 * * 1` → `0 0 * * *` へ日次化 | **週次ボスが生成されない事故の修正**。曜日指定の解釈違いが原因だった。`claimGeneration` が週1回の生成を保証するため日次実行でも二重生成しない。発火漏れ・遅延を翌日に自己修復できる |
| WebSocketメッセージ契約の変更（T-182） | イベントバトルのクライアントとサーバーで同時に更新される。旧版のアプリを開いたままの端末は再読み込みが要る |
| `/register` の形式強制 | 表示名の一意性検証を追加。既存の登録済み端末には影響しない |
| `/admin/*` の認可分離 | 管理系エンドポイントを `ADMIN_TOKEN` で分離。**デプロイ前に本番へ `ADMIN_TOKEN` の secret 設定が要る**（未設定だと管理系が使えない。学習者側の機能には影響しない） |
| Durable Object `InviteRateLimitDo`・`RegistryDo` の追加 | 招待コードのレート制限と、登録枠・表示名予約をDO化した。`wrangler.toml` にバインディングとマイグレーション（v4・v5）を追加済み。`RegistryDo` は初回アクセス時にKVの `member:*` から索引をbackfillする |
| 設問IDが53件消える | 除外題材の差し替えに伴う（新規は196件）。既存ユーザーの学習データへの影響は下記「既存ユーザーへの影響」を参照 |

### 品質の改善

- **TOEICが扱わない題材を全廃**（訴訟・破綻・人員整理・個人の不利益）。語彙バンクの8語を差し替え、設問・選択肢からも除いた

- **Part3/4の話者性別の取り違え10箇所を訂正**。設問・解説が「男性は」と書いているのに音声は女性、という不整合があった

## 開発側の変更

### コンテンツの出所を機械で強制するようにした

CLAUDE.md の不変条件「工程を経ていないコンテンツは配信しない」を守る仕組みが無く、実際に記録の無いパックが配信されていた。`beb verify-content` に検査を追加し、CIで実行する。

- 工程記録の3フィールド（`reviewedBy`・`reviewedAt`・`reviewMethod`）の有無
- `pack.origin` と工程名の整合
- 敵対的検証の記録（`content/drafts/<packId>.adversarial.tsv`）の存在
- 全設問の判定が揃っていること・`accept` 以外が残っていないこと

配信中の24パックすべてに実施モデル名が入っている（内訳は Fable 12件・Fable 5 10件・別モデル3並列 2件）。2026-08-13に、それまで一度も通していなかった9パック490問と読解R-2の3パックをFableで読み、63件の指摘を修正した。

### 完了条件そのものを測る検査を足した

条件が未達のまま完了扱いにできた原因は、条件を測る仕組みが無かったことにある。`contentLint` に2つ追加した。

- ⑩ 正答位置の1次マルコフ的中率が、同条件のランダム列の95%点を超えていないか
- ⑪ 解説が誤答選択肢に言及しているか

あわせて①（scriptの応答部と正解選択肢の一致）を警告からビルド失敗へ昇格した。

## レビューで見つかった不変条件の穴（2026-08-13追加）

dev→mainのレビューで6件の指摘があり、いずれも実コードで成立を確認して修正した。**4件はP1（「直したはずの不変条件が本番条件では成立しない」種類）**である。

| # | 内容 | 修正 |
|---|---|---|
| 1 | 表示名の一意性判定が新設の逆引きキーだけを見ており、**デプロイ前から存在するメンバーの表示名が保護されなかった**。なりすまし防止が既存ユーザーに効かない | `RegistryDo` の初回アクセス時にKVの `member:*` から索引をbackfillする |
| 2 | 週次生成が途中で失敗すると、翌日の再実行で**更新済みメンバーのEMAが二度平滑化**された（実力の過小評価） | 反映済みの週を `emaUpdatedForBossId` に記録して冪等にする |
| 3 | 音声取得に失敗してもパックを同期済みにしていた。skip判定は先頭3件しか見ないため、**4件目以降だけ失敗すると永久に再取得されなかった** | 1件でも失敗したらハッシュを確定しない。音声fetchに15秒のタイムアウトも追加（無かったため1件のハングで同期全体が止まりえた） |
| 4 | 登録上限と表示名予約がKVのread-then-writeで、**並行登録で突破できた** | `RegistryDo`（単一インスタンスDO）で枠確認・表示名確認・確定を1RPCに閉じる |
| 5 | ゴースト撤回が直近1週しか辿らず、**複数週で使われた場合に古い週へ正誤詳細が残った**（同意画面の「撤回すると即時削除」を満たさない） | `usedBossIds` で使用履歴を持ち全週から消す |
| 6 | cronが4週を超えて止まると、取りこぼした週のDOが**二度と掃除されなかった** | 掃除済み境界を永続化し、次回そこから追いつく |

この修正で `wrangler.toml` に **`REGISTRY` バインディングとマイグレーション v5** が加わった。

## 既存ユーザーへの影響

- **全パックのハッシュが変わるため、初回起動時に全パックを再ダウンロードする**（音声込み。従量課金の回線では通信量に注意）
- **設問IDが53件消える**（設問総数は1855→1998件）。除外題材の差し替えに伴うもので、消えた設問を参照するSRSカードは出題できなくなる。カードは削除せず残す（将来パックが戻れば再び出題できるため）。ホームの「SRS期限」バッジは出題できるカードだけを数えるよう修正済みで、消せない件数が残ることはない
- **`attempts`（解答履歴）は追記のみで、削除も更新もしていない**。消えた設問への解答記録もそのまま残る
- レート・SRSの間隔テーブル・レイドの週境界は変更していない
