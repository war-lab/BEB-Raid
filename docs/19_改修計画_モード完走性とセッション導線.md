## 3. 事前決定事項（J-57〜J-61の正文）

### 3.1 単独モードの問数選択とシャッフル（J-57）

- **Part2瞬発・Part5単独モードに問数選択（10問/20問/50問）を追加する**。既定は20問。「全問」オプションは置かない（プール全問=Part5で437問の完走不能セッションが生まれる問題の再発防止。完走ニーズはM4以降で再検討=6節）。
- 選択値はsettingsの新キー `singleModeCount` に保存し、画面遷移・再起動を跨いで復元する（T-112の`QUEST_DURATION_KEY`と同じパターン。Part2/Part5で共通の1キーでよい）。
- **出題は毎回シャッフルして先頭N問を取る**（`engine/shuffle.ts`の`shuffle`。rng注入でテストを決定化する）。従来はプール順固定のため「中断→破棄を繰り返すと毎回同じ最初の問題だけをやり、後半の問題に永遠に到達しない」構造だった。
- UIの置き場所: Part2瞬発は既存の再生方法選択モーダル（T-116(8)で画面中央固定化済み）に問数チップを追加する。Part5は同型の選択モーダル（問数チップ+開始/キャンセル）を新設する。Part5は従来即時開始だったが、選択値が保存されるため2回目以降は「開く→開始」の2タップで済む。

### 3.2 語彙SRS仕分けの既知永続化と区切り（J-58）

- **「知ってる」スワイプで卒業済みSRSカード（`graduatedAt=now`）を作成して永続化する**。従来は`handleKnown`がインデックスを進めるだけで何も記録せず、「知ってる」と答えた語が次回入店時にまた仕分けキューへ出ていた（候補フィルタが「srsCards未登録の語」のため）。
- 卒業済みカード方式を選ぶ理由: (a) DBスキーマ変更なしで完結する、(b) エクスポート/インポートで自然に引き継がれる、(c) `getSrsQueue`のactiveフィルタ（`graduatedAt !== null`を除外）により復習キューへ出ない、(d) 仕分け候補フィルタ（srsCards登録済みを除外）により再出題されない、(e) **既知語が後の学習で誤答された場合、既存の`addSrsCard`が「卒業済みカードへの再追加=stage0から学習し直す」仕様のため、自動的にSRS学習へ編入される**（意図した相互作用。コメントに明記すること）。
- 実装は`engine/srs.ts`に専用関数（例: `markVocabKnown(db, word, now?)`）を追加する。既存のactiveカードがある語に対しては何もしない（多層防御。通常は候補フィルタで到達しない）。作成するカードは `stage: 0, dueAt: now, lapses: 0, introducedDate: toDateString(now), graduatedAt: now, sourceQuestionId: null`。
- **仕分けは1回20語で区切る**。20語仕分けるごとに中間画面「仕分けを20語終えました（残りN語）」＋「続けて仕分ける/ホームへ」を出す。600語を前に「終わりが見えない」圧を removal する。
- **復習フェーズから仕分けへの直行導線を追加する**。復習画面のステータス帯に「仕分けへ」ボタンを置き、タップで復習キューを消化せず仕分けフェーズへ移る（復習キューはDB上未消化のまま=次回入店時にまた復習から始まる。仕分けから復習へ戻る導線は不要）。従来は復習キューを全消化するまで仕分けに到達できない一本道だった。

### 3.3 シャドーイングの開始位置と素材間移動（J-59）

- **マウント時にattemptsの`shadow:<id>`記録を読み、未実施素材の先頭から開始する**。全素材実施済みなら素材1から（周回扱い）。従来は`index`が常に0始まりで、完了記録を書いているのに画面が参照せず、毎回同じ素材1が出ていた。
- **「次の素材へ」を常時表示する**（3周完了前でも移動可。従来は3周完了後の「次へ」か音声エラー時のスキップしか移動手段が無かった）。「前の素材へ」も`index > 0`のとき表示する。
- **実施ログの記録規約は変えない**（3周完了時のみ`shadow:<id>`を記録=J-13。途中で次へ移った素材は未実施のまま）。
- ステータス表示を「素材 n/30（m/3周）」へ変更し、実施済み素材を表示中は「実施済み」の注記を出す。
- 素材一覧からの選択UIは見送り（6節）。

### 3.4 空パック時のフィードバック（J-60）

- **「今日のクエスト」「レイドに挑む」で生成パックが0問だった場合、無反応にせずメッセージを表示する**。従来は`items.length === 0`で黙ってreturnし、ボタンを押しても何も起きなかった（3分クエスト=SRS復習中心の構成のため、SRS期限・新規カードが無い初期状態で高確率で発生する既知の挙動が放置されていた）。
- メッセージ文言: 「今は出題できる問題がありません」を基本とし、3分選択時のみ「3分クエストはSRS復習が中心です。復習カードが無いときは7分・15分をお試しください」を続ける。表示位置は主ボタン直下（`.home-pool-empty-hint`と同様の様式）。自動では消さず、セッション開始成功か画面遷移で消えればよい。
- RaidScreenの「レイドに挑む」も同様に「今は出題できる問題がありません」を表示する。

### 3.5 セッションの途中終了と中断確認の具体化（J-61）

- **DrillScreenの解説表示中（正誤確定後）に「ここで終了して結果を見る」の副次導線を追加する**。タップで確認なしに`navigate('result')`する（ResultScreenはT-109で`snapshot.attemptIds`基準の全体集計になっているため、解答済み分のリザルトがそのまま正しく表示される。「ホームへ」で既存どおり`completeSession`がセッションを破棄する）。従来は全問完走以外にリザルトへ到達する手段が無く、途中で電車を降りるときに成果表示を見られなかった。
- 表示条件: 解説表示中（`result !== null`）かつ残り問題が1問以上あるとき（最終問の解説では既存の「次へ」がリザルトへ進むため出さない）。`secondary-action`様式で「次へ」の下に置く。
- **中断・破棄の確認メッセージを具体化する**。`CONFIRM_DISCARD_MESSAGE`（HomeScreen定義・RaidScreenも使用）を「進行中のセッション（残りN問）を破棄して新しく始めますか？」のように残り問数入りへ変更する（定数文字列から関数へ。何を破棄するのか分からない不安を減らす）。
- 複数の再開スロット（クエストと単独モードのセッションを別々に保持する）は見送り（6節。J-57の問数選択で437問級のセッションが生まれなくなるため実害が大きく減る）。

### T-118 単独モード（Part2瞬発・Part5）の問数選択とシャッフル 🟢

- **背景**: `startSingleMode`はプール内の該当format全問を1セッションにする。実コンテンツでtext_blank=437問・audio_qa=150問あり、「Part5を始めたら437問終わるまでリザルトが出ない」完走不能セッションになる（時間チップはJ-54で「今日のクエスト」専用と確定済みのため、単独モードには長さの制御が一切無い）。さらに出題がプール順固定のため、中断→破棄を繰り返すと毎回同じ最初の問題だけを解くことになり、プール後半に永遠に到達しない。
- **変更ファイル**: `screens/HomeScreen.tsx`・`services/settingsKeys.ts`（`SINGLE_MODE_COUNT_KEY`新設）・`styles/components.css`・各テスト。
- **実装指示**: 3.1節（J-57）のとおり。
  1. `startSingleMode`を「`shuffle(filtered)`の先頭N問」に変更する（`engine/shuffle.ts`の既存`shuffle`を使用。テストではrng注入で決定化——ただし`startSingleMode`は画面内関数のためrngを直接注入できない。`shuffle`をモジュールモックするか、選択結果の問数・重複なしを検証する形でよい）。
  2. 問数チップ（10/20/50。既定20）をPart2の既存モーダルに追加し、Part5用に同型の選択モーダル（問数チップ+開始/キャンセル）を新設する。選択値は`SINGLE_MODE_COUNT_KEY`へ保存しマウント時に復元（T-112の実装パターンを踏襲。不正値は既定20へフォールバック）。
  3. プールがN問未満のときはある分だけで開始する（0問なら開始しない=T-121が表示を足す）。
- **完了条件**: 新規テスト「選択した問数でセッションが始まる」「シャッフルされる（プール順と一致しない、または全件から抽選されることの検証）」「選択が保存・復元される」「プールが問数未満でもある分だけで開始する」。既存のPart2瞬発（partialAudioMode含む）・Part5テストの回帰。2.3節の全体検証。

- **背景**: 仕分け候補は「SRSカード未登録の全語彙」で現在600語。かつ「知ってる」はインデックスを進めるだけで何も永続化しないため、**次回入店時に既知と答えた語がまた仕分けキューに出る**（仕分けし切っても翌日ほぼ全部やり直し）。また画面が「復習キュー全消化→仕分け→完了」の一本道で、復習が溜まった日は仕分けに到達できない。docs/02 4節は「知らない語だけSRSへ」としか定めておらず、既知判定の記憶が未設計だった。
- **変更ファイル**: `screens/VocabScreen.tsx`・`engine/srs.ts`（関数追加のみ。既存関数のシグネチャは変えない）・各テスト。
- **実装指示**: 3.2節（J-58）のとおり。

  2. 仕分けフェーズを20語で区切り、中間画面（「続けて仕分ける（残りN語）/ホームへ」）を挟む。
  3. 復習画面のステータス帯に「仕分けへ」ボタンを追加する（復習キュー未消化のまま仕分けフェーズへ移る）。
- **完了条件**: 新規テスト「知ってるスワイプで卒業済みカードが作成され、再マウント後の仕分け候補に出ない」「復習キューにも出ない」「20語で中間画面が出て続行できる」「復習画面から仕分けへ直行できる」「既知語が後からaddSrsCardされるとstage0の学習カードに戻る（既存仕様の結合確認）」。既存VocabScreenテストの回帰。2.3節の全体検証。

### T-120 シャドーイングの開始位置と素材間移動 🟢

- **背景**: `index`が常に0始まりで、3周完了時に`shadow:<id>`のattemptを記録しているのに画面側がそれを一切参照しないため、**毎回同じ素材1が出る**。「次へ」は3周完了後にしか出ず（音声エラー時のスキップを除く）、1周だけして次の素材へ移ることもできない。30素材あるのに実質素材1専用画面になっていた。
- **変更ファイル**: `screens/ShadowingScreen.tsx`・各テスト。
- **実装指示**: 3.3節（J-59）のとおり。
  1. マウント時にattemptsから`shadow:`プレフィックスの記録を読み、実施済みIDの集合を作る。初期`index`は未実施素材の先頭（全実施済みなら0）。
  2. 「次の素材へ」を常時表示（3周完了後の既存「次へ」と統合してよい）、「前の素材へ」を`index > 0`のとき表示。素材移動時は既存`handleNext`と同様にlaps/completed/positionMs/audioErrorをリセットする。
  3. ステータスを「素材 n/30（m/3周）」形式にし、実施済み素材の表示中は「実施済み」注記を出す。
  4. 実施ログの記録規約（3周完了時のみ）は変えない。
- **完了条件**: 新規テスト「実施済み素材を飛ばして未実施の先頭から始まる」「全実施済みなら素材1から始まる」「3周完了前でも次の素材へ移動できる（attemptは記録されない）」「前の素材へ戻れる」。既存ShadowingScreenテストの回帰。2.3節の全体検証。

### T-121 空パック時のフィードバック 🟢

- **背景**: HomeScreenの`startSessionAndNavigate`とRaidScreenの`handleChallenge`は生成パックが0問のとき`items.length === 0`で黙ってreturnし、ボタンを押しても何も起きない。3分クエストはSRS復習中心の構成のため、SRS期限・新規カードが無い状態（新規ユーザーの典型）で高確率で発生する。既存テストにも「3分は期限カードが無いと空パックになるため仕込む」と書かれており、既知の挙動が無処理で放置されていた。
- **変更ファイル**: `screens/HomeScreen.tsx`・`screens/RaidScreen.tsx`・各テスト。
- **実装指示**: 3.4節（J-60）のとおり。空パック時にメッセージstateを立てて主ボタン直下に表示する（「今は出題できる問題がありません」+3分選択時のみ補足文）。セッション開始成功時・単独モード開始時にはメッセージをクリアする。RaidScreenも同様（補足文なしの基本文言のみ）。
- **完了条件**: 新規テスト「SRSカードなしで3分クエストを開始するとメッセージが表示される（遷移しない）」「7分等で開始成功するとメッセージが消える」「レイドに挑むで空パックならメッセージ表示」。既存クエスト開始・レイド挑戦テストの回帰。2.3節の全体検証。

- **変更ファイル**: `screens/DrillScreen.tsx`・`screens/HomeScreen.tsx`（メッセージ定数→関数化）・`screens/RaidScreen.tsx`（同関数の利用）・各テスト。
