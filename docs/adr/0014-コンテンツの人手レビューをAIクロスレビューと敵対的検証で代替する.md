# 0014. コンテンツの人手レビューをAIクロスレビューと敵対的検証で代替する

- **日付**: 2026-08-13
- **ステータス**: 承認済み（事後記録。判断そのものは2026-08-06にJ-119として確定し、docs/32 3節に正文がある）
- **関連**: J-119、T-355、[31](../31_敵対的検証棚卸し.md) K-76、[32](../32_改修計画_敵対的検証.md) 3節・8節、[ADR 0006](0006-読解パートの完成方針.md) 判断5、CLAUDE.md「破ってはいけない不変条件」

## 背景

CLAUDE.md と [04](../04_データ設計.md) 5節は、コンテンツの工程を「LLM生成＋人手レビュー＋TTS」と定め、これを不変条件として扱ってきた。

しかし2026-08-06の敵対的検証（K-76）で、この不変条件が実態と乖離していることが判明した。配信中のパックには `origin` に「人間目視レビュー待ち」と記載されたまま配信されているものがあり、人手レビューを経ずに配信されたコンテンツが既に存在していた。

原因は工程の設計そのものにある。人手レビューの担い手は発起人1人だけで、対象は20パック・1,400問を超える。レビューが追いつかないまま生成だけが進み、不変条件が空文化していた。

本ADRは、この判断を後から記録するものである（adr/README.md の「事後記録」に該当）。判断は既に docs/32 3節のJ-119として確定し、実装（T-355）も完了している。ウェーブ0〜9の92タスクからADRが1件も起票されていなかったため、不変条件を書き換えた判断だけでも独立して辿れるようにする。

## 検討した選択肢

**案A: AIクロスレビュー＋敵対的検証を人手レビューの代替とする**

利点は、レビューの担い手が1人に依存しなくなり、生成の速度に検証が追随できること。欠点は、品質保証の主体が人からモデルへ移ることと、同一系列のモデルが共有するバイアスは検出できないこと。

**案B: 人手レビュー必須を維持し、未レビューのパックは配信を止める**

利点は不変条件がそのまま守られること。欠点は、既に配信済みのコンテンツを引き上げる必要があり、学習者が使える問題数が大きく減ること。レビューのボトルネック自体は解消しない。

**案C: 不変条件から工程要件を外す**

利点は運用が軽くなること。欠点は、著作権リスク（市販教材との類似）と品質の担保が誰の責任でもなくなること。不変条件を置いた元の目的を失う。

## 判断

案Aを採る。

読解（Part6/Part7）は [ADR 0006](0006-読解パートの完成方針.md) 判断5に従い、人手レビュー必須を維持する。読解は本文が長く、著作権上の類似判定と論理の妥当性の両方で人の判断を要するためである。

読解以外は「LLM生成＋別モデルによるクロスレビュー＋6観点の敵対的検証＋TTS」を正規の工程とする。6観点は二重正答・不当な易しさ・話者と設問の整合・題材の適格性・実在情報の混入・統計的偏りで、定義は docs/32 8.1節を正本とする。

クロスレビューに使うモデルは、生成に使ったものとは別系列にする。同じモデルに自分の生成物を検証させても、共有するバイアスは検出できないためである。

工程の記録は次の2箇所に残す。判定の一次記録は `content/drafts/<パックID>.adversarial.tsv`（1問1行・verdictは accept / revise / reject）。パック側のメタデータは `pack.origin`（書式は docs/32 8.2節）と `pack.reviewedBy`・`reviewedAt`・`reviewMethod`。`verdict` が revise・reject の問題は、修正して再検証するまで配信しない。

## 影響・トレードオフ

品質保証の主体が人からモデルへ移る。同一系列のモデルが共有するバイアス（例えば特定の出題形式を一律に妥当と判断する傾向）は、この工程では検出できない。定期的に人手で抜き取り検査を行い、工程が機能しているかを確認する必要がある。

**この工程は現時点で機械検査により強制されていない。** `beb verify-content` にも `contentLint` にも、配信パックが敵対的検証の記録を持つことを検査する処理が無い。実際、2026-08-13時点で `pack-p2-s-003` は記録が無いまま配信されており、`pack.reviewedBy` 系の3フィールドは全パックで未記入、`pack.origin` も規定書式に更新されていない。不変条件を文書だけで宣言して機械検査を持たない状態は、同じ逸脱を繰り返す。是正状況は [STATUS](../STATUS.md) 1.4節で追跡する。

見直す条件は次の2つである。第1に、抜き取り検査でAIクロスレビューの見落としが継続的に見つかった場合は、人手レビューの必須範囲を読解以外にも戻す。第2に、配信パック数が1人の人手で扱える規模まで縮小した場合は、案Bへ戻すことを再検討する。

## Amendment（2026-08-13）

**適用範囲を全コンテンツへ広げ、クロスレビューの実施モデルをFableに固定する**（発起人判断）。

起票時は読解（Part6・Part7）を対象外とし、[0006](0006-読解パートの完成方針.md) 判断5の人手レビュー必須ゲートを残していた。同判断は本日撤回された（0006のAmendment）。読解も含め、AIクロスレビュー＋敵対的検証を人手レビューの代替として使ってよい。

**実施モデルはFableとする。** 生成はClaude系のエージェントが行っているため、同系列のモデルで読むと「生成に使ったのとは別のモデルで読む」という要件（J-119）を満たさない。2026-08-13に9パックをclaude-sonnet-5で読んだが、この基準では要件を満たさないため、Fableで読み直す。

実施モデルはパックごとに `build.ts` の `CROSS_REVIEW_MODEL_BY_PACK_ID` に記録し、`pack.origin` と `pack.reviewMethod` へ反映する。表に載っていないパックは工程名からクロスレビューの段が落ちるため、未実施のまま配信すると `beb verify-content` の記録検査では止まらないが、出所表記が「敵対的検証のみ」になって区別できる。
