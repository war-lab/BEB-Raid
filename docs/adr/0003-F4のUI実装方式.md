# 0003. F4のUI実装方式（ルーターレス・Zustand・SVG自作チャート）

- **日付**: 2026-07-10
- **ステータス**: 承認済み
- **関連**: T-16〜T-23、docs/10（F4〜F6実装計画）3節、docs/05 2節、docs/07 8節

## 背景

F4（学習モードUI）着手時点で、画面遷移・状態管理・チャート描画の実装方式が docs に確定記載されていない（05は「Zustand程度の軽量状態管理」とスタック候補を挙げるのみ）。AIエージェントによる自走実装を前提とするため、着手のたびに方式選定で揺れないよう事前に確定する。

## 検討した選択肢

1. **画面遷移**
   - react-router 導入: URL連動・ブラウザ履歴が無料で付くが、M1は6画面・deep-link不要・静的PWAで履歴要件がない。依存とバンドルが増える。
   - **ルーターレス（Zustand の screen 状態で切替）**: 依存ゼロ・実装最小。ブラウザ戻るボタンが効かない欠点は、standalone PWA（ブラウザUIなし）が主用途のM1では影響が小さい。
2. **状態管理**
   - React useState/Context のみ: 画面横断状態（セッション進行・設定）でバケツリレーが増える。
   - **Zustand**: 05に記載済みの想定スタック。正本は常にIndexedDBとし、Zustandは画面状態と表示キャッシュに限定する。
3. **チャート（S6の折れ線・横棒・ヒートマップ）**
   - Recharts等のライブラリ: 実装は速いが、07の8節の規定（凡例なし・終端直付け・レーダー禁止・数表ビュー・トークン色）とデフォルト挙動が衝突し、打ち消し設定が本体より大きくなる。バンドルも増える。
   - **素のSVG自作**: 3種とも単純な図形で、規定を直接実装できる。依存ゼロ。

## 判断

ルーターレス＋Zustand＋SVG自作チャートで実装する。決め手は「M1の画面数・チャート数に対して依存追加のコストが利得を上回る」こと、およびオフラインPWAのバンドル最小化。

## 影響・トレードオフ

- ブラウザ履歴・deep-linkは効かない。M2で共有URL・画面復元が必要になった時点でルーター導入を再検討する（screens/ 配下の画面分割はルーター移行を妨げない構造にしておく）。
  - **その後の実態（2026-08時点）**: ルーターは導入しないまま、`navigate()` で `history.pushState` し `popstate` で前画面へ戻る実装を入れた（`store/appStore.ts`・`App.tsx`。標準の戻る操作とAndroidのバックキーに対応するため。popstate時に `audioPlayer.stop()` も行う＝T-221）。deep-link（URLからの直接復元）は引き続き不可である。
- チャートの表現力はライブラリ比で低い。予測帯（M2のJ-1解除時）追加時に自作の複雑度が閾値を超えたら再評価する。
