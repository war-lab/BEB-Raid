# 0004. M2の設計確定と実装方式（自走基盤）

- **日付**: 2026-07-14
- **ステータス**: 承認済み
- **関連**: T-39〜T-66、docs/12（M2タスク分解）、docs/13（M2実装計画）3節、docs/02 3節・8節、docs/03 1.2・5.5・8節、docs/04 2〜3節、docs/05 5節

## 背景

M2（リスニング深化＋カリキュラム）は 06 に定義があるが、02〜05 の設計には実装着手に足りない穴が複数あった（P2→P3の達成条件・到達予測の算出式・criteriaJson のスキーマ・ディクテーション採点・シャドーイングの記録設計・先読みトレーナーのUI仕様・timing の取得手段・BYOK の技術仕様・レビューUIの実体）。M1 と同様に Sonnet クラスのエージェントが1タスク=1セッションで自走する前提のため、着手のたびに設計判断で停止・暴走しないよう、着手前に一括で確定した（判断一覧は 12 の1.2節 J-9〜J-29、正文は 13 の3節。契約改訂タスク T-41〜T-44 が設計正本 02/03/04/05 へ反映する）。

## 主要な判断と理由

1. **timing は推定アライメント（J-26）**: Piper は単語タイムスタンプを公式に出力しない前提で設計する。強制アライメントツール（aeneas 等）の導入は依存・環境構築コストが大きく、カラオケハイライトの用途（読み上げ追従の目安）には音節数近似の按分で足りる。精度不足時は文単位ハイライトへ縮退という逃げ道を先に確定しておく。
2. **再生速度は HTMLAudioElement + preservesPitch（J-27）**: Web Audio の `AudioBufferSourceNode.playbackRate` はピッチが変わり、タイムストレッチ実装（SoundTouch等）は依存追加になる。主要ブラウザで実装済みの `preservesPitch` を rate 指定時のみの別経路として併設するのが依存ゼロで最小。
3. **BYOK は Anthropic API を fetch 直呼び・SDKなし（J-14）**: 05 の既定（CORS オプトインで直接呼ぶ）に従い、app のバンドルに SDK を足さない。対話履歴は永続化しない（データ設計・プライバシー面の複雑化を避け、M2 は「その場で聞ける」価値に絞る）。
4. **ディクテーションはワードバンクのみ・レート更新対象外（J-12/J-29）**: タイピングは表記ゆれ採点の設計が重く、電車内の操作性にも合わない。レートは選択式の得点式（03の5.3）前提のため対象外とし、tagStats（弱形タグ）にだけ反映して L1 卒業判定の入力にする。
5. **シャドーイングは正誤なしの実施ログ（J-13）**: 自己完結型で正誤が出ない機能を無理に採点せず、`shadow:` プレフィックスの attempts 追記（ストリーク寄与あり・統計除外）とする。`vocab:` プレフィックスの前例と同じ除外方式で集計系への影響を封じる。
6. **フェーズ条件・到達予測は暫定値を固定して外出し（J-15/J-16）**: P2→P3 条件や回帰の窓幅（28日）は理論的正解がなく、ドッグフード実測で調整する類の値。「暫定と明記して設定ファイル/定数に外出しし、まず動くものを作る」という M1 の quickPackConfig / T-34 実測補正と同じ運用に乗せる。
7. **レビューUIは packages/review-ui + dev ミドルウェア（J-28）**: ブラウザからのローカルFS書き込みは File System Access API の互換問題を追わず、T-37 で確立した Vite dev ミドルウェア方式（contentAssetsPlugin と同型）でローカルAPIを立てる。既存 review-import と出力互換にし、CLI/TSV 運用との併存を保つ。
8. **コンテンツ増強は M1 方式踏襲（J-21）＋ Part3/4 等をスコープに明記（J-9）**: ランタイムAPI呼び出しなし・エージェント直接執筆・クロスレビューの方式は M1 で実績があり、ユーザーの明示方針でもある。先読みトレーナー・L3・P2 配分が Part3/4 コンテンツを要求するのに 06 の M2 定義に量が無かったため、最小量（各10セット）を明記した。Part6/7 は M3 以降。

## 影響・トレードオフ

- 推定 timing は単語単位の精度が低い。ハイライトが「目安」であることをUIに明記し、体感で許容できなければ文単位に縮退する（それでも 02 の3.3 L1 の用途は満たせる）。
- preservesPitch 非対応環境ではピッチが変わる。対象ブラウザ（iOS Safari / Android Chrome の現行版）では対応済みのため実害は限定的。
- フェーズ条件・予測式の暫定値は誤っている可能性が高い前提で運用する（ドッグフードでの実測→ curriculumConfig / 定数の調整。判定ロジックと値を分離してあるので調整は安価）。
- 対話履歴の非永続化により、AI質問の続きは画面を離れると失われる。M2 の利用実態で不満が出たら永続化を再検討（新ストア追加=C-2 改訂が必要）。
