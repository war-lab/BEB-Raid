# ADR（Architecture Decision Records）

設計正本（docs/01〜08）に書かれていない技術判断を記録する。「なぜそうしたか」を後から辿れるようにすることが目的。

## 運用ルール

- **対象**: ツール・ライブラリ選定、実装方式の選択、スコープ解釈、正本間で読みが分かれた点の判断など。正本（01〜08）を変更する判断は該当ドキュメント自体を更新し、ADR はその「なぜ」を補足したい場合にのみ併用する。
- **タイミング**: 判断を実装に反映する PR と同じ PR に含める（後追いで書かない。ただし既に実装済みの判断を遡って記録する「事後記録」は明記の上で可）。
- **番号**: 4桁連番（`0001-タイトル.md`）。欠番を作らない。
- **ステータス**: `提案中` → `承認済み` → （必要なら）`廃止`（後継 ADR へのリンクを残す）。承認済み ADR の本文は書き換えず、**判断そのものが変わった**場合は新しい ADR を起こして旧 ADR を廃止にする。
- **判断は維持したまま前提・実装が変わった場合**は、本文を書き換えず末尾に `## Amendment（日付・タスクID）` を追記し、以後の正文をそちらへ移す（0005・0007・0009・0012・0013 が該当）。ヘッダに `**改訂**:` 行を置き、どの節が正文かを示す。事実誤り（実装値の追随漏れ等）の訂正は本文中に訂正注記として入れてよい。
- **書式**: [template.md](template.md) を使う。
