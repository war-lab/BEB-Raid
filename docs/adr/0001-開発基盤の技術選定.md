# 0001. 開発基盤の技術選定（npm workspaces / tsc dist 配布 / Prettier md 除外）

- **日付**: 2026-07-07（事後記録: T-01 実装時の判断を ADR 運用開始に伴い遡って記録。原典は T-01 のコミットメッセージ）
- **ステータス**: 承認済み
- **関連**: T-01（08の3節 F1）、docs/05 2節

## 背景

T-01（リポジトリ構成・開発基盤）で、docs/05 が定めるスタック（React + TypeScript + Vite、CLI は TS/Node）の範囲内でも決まらない実装上の選択が3点あった。

## 検討した選択肢と判断

### 1. パッケージ管理: npm workspaces を採用

- 採用: **npm workspaces**（追加ツール不要で運用負荷最小）
- 不採用: pnpm / turborepo — 現規模（3パッケージ・ビルド数秒）では過剰。ビルド時間かパッケージ数が増えて困ってから移行しても手戻りは小さい

### 2. 型共有: shared-schema は tsc で dist を配布

- 採用: **tsc ビルドで dist を配布**し、app（bundler 解決）/ cli（NodeNext）双方から参照
- 不採用: TypeScript project references — 参照設定が複雑になる割に、この規模では得るものが少ない

### 3. Prettier: `*.md` を整形対象から除外

- 採用: **Markdown を除外**
- 理由: docs/ は設計正本であり、整形ツールによる意図しない差分（表の整形など）がレビュー履歴を汚すのを防ぐ

## 影響・トレードオフ

- npm workspaces はタスクランナー機能（依存グラフに基づく並列ビルド・キャッシュ）を持たない。ルート package.json のスクリプトでビルド順を手書きしており、パッケージが増えると保守負荷が上がる可能性がある。その時点で turborepo 等の導入を再検討する。
- shared-schema の変更は dist の再ビルドが必要（`npm run build -w @beb-raid/shared-schema`）。ビルド忘れによる古い型の参照に注意。
