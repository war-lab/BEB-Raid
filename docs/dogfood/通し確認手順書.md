# 通し確認手順書（T-37 / T-40のAI支援範囲）

正本: 08のT-37行、06のM1、03の3節。P0診断→クイックパック→誤答→key語彙SRS→類題出題→SRS復習の一連を、実データの具体例付きで確認する手順。

## 前提

- コンテンツが配信済みであること。2026-08-13時点の配信内容は21パック1536問で、内訳は語彙カード650・Part5系（text_blank）437・Part2（audio_qa）213・ディクテーション86・読解（text_passage）70・Part3/4セット50・シャドーイング30である。
- **確認するURLに注意する**。公開URL（`https://war-lab.github.io/BEB-Raid/`）へのデプロイは main への push でのみ走る。dev に統合済みでも main へ未マージの変更は公開URLに載っていないため、dev の内容を確認したい場合は公開URLではなく、ローカルで `npm run build -w @beb-raid/app` してから `npm run preview -w @beb-raid/app` を起動し、同一LANの実機からそのアドレスを開く。
- 新規プロファイル（未診断状態）で開始する。ブラウザのプライベートウィンドウ、またはエクスポート済みデータの退避後に IndexedDB をクリアして確認する。

## 手順

### ステップ1: P0診断

1. アプリを開くと診断画面が表示されることを確認する。
2. 表示名を入力し、自己申告TOEICスコアは空欄のまま診断を開始する。
3. L15問・R15問、計30問に解答する。
4. 完了画面でL/Rの初期レートが表示され、予測スコア帯が**表示されない**こと（J-1・M1対象外）を確認する。
5. ホーム画面に遷移する。

### ステップ2: クイックパック開始

1. ホーム画面で「今日のクエスト」（既定7分）をタップする。
2. 語彙カード・Part2・Part5が混在した問題列が出題されることを確認する。
3. Part2やPart5の問題で、**意図的に誤答を選ぶ**（例: keyVocabに `submit` を含む問題で不正解を選ぶ）。

### ステップ3: key語彙SRSへの登録確認

1. セッション完走後、リザルト画面で「誤答N問を復習デッキに追加した」表示を確認する。
2. ホーム画面→語彙SRSに遷移する。
3. 誤答したkeyVocab（例: `submit`）が仕分けモードまたは復習モードの候補に含まれることを確認する（新規カードとして追加されている）。

### ステップ4: 類題出題の確認

1. 翌セッション相当として、再度「今日のクエスト」を開始する（同日内でも、SRS期限が来ていなくても弱点タグ・key単語の重み付けは効くため、複数回試行して確認してよい）。
2. 出題される問題に、誤答したkeyVocabを含む**類題**（`keyVocabSimilarS.ts` 由来の57問のいずれか）が含まれることを確認する。
3. 出題理由ラベル（ステータス帯）が表示され、なぜこの問題が出たか分かることを確認する。

### ステップ5: SRS復習の確認

1. srsCardsに追加されたカードの `dueAt` が到来するまで待つ（初回は翌日=1日後）。待たずに確認する場合は、**端末の日付を進めるのではなく `dueAt` を手動で近づけたテストデータを使う**。端末時計を進めると、SRSのdueAtクランプ（T-303）・ストリークの未来値巻き戻し（T-304）・rankPointsの単調化（T-305）が働き、時計を戻した後も副作用が残る。
2. 語彙SRS画面の復習モードで、当該カードが期限到来カードとして出題されることを確認する。
3. 4択リコールテストに解答し、自己評価3段階（もう一回/OK/余裕）を選ぶ。
4. 次回の `dueAt` が間隔テーブル（1→3→7→14→30→60日）に従って更新されることを確認する（開発者ツールでIndexedDBを確認するか、エクスポートJSONで確認する）。

## 結果の記録

各ステップの結果（成功/失敗と具体的な症状）は本ファイル末尾か `docs/history/` の該当月へ追記する（STATUS.mdは「現在地のみ・300行以内」の方針で、個別タスク行は残していない）。問題が見つかれば `.github/ISSUE_TEMPLATE/bad-question.md`（コンテンツ起因）または通常のバグ報告として記録する。
