# KPI週次確認手順（T-38 / T-40のAI支援範囲）

正本: 08のT-38行・5.2節、06の4節。ドッグフード期間中（2週間）、週次でKPIを取り出す手順。

## 追うKPI（06の4節）

- **週あたり学習日数**（最重要）
- 電車セッション数/週
- SRS消化率

## 手順

1. アプリの設定画面から「エクスポート」を実行し、JSONファイルをダウンロードする（ファイル名に日付が入る）。
2. ターミナルで以下を実行する。

   ```
   cd packages/cli
   npm run build
   node dist/index.js kpi <ダウンロードしたエクスポート.json>
   ```

3. 週（ISO週。月曜始まり）ごとの表が出力される。

   ```
   週      学習日数  セッション数(近似)  SRS消化率
   2026-W29  5         6                   82%
   ```

4. 学習日数・セッション数・SRS消化率を週次のメモ（Issueやスプレッドシート等）に記録する。

## 集計値の注意点（近似であることの明記）

- **セッション数**: `activeSession` の完了記録から厳密に取れないため、attempts を30分間隔でクラスタリングした近似値。電車の往復で2セッション行った日でも、間隔が短ければ1セッションとして数えられる場合がある。
- **SRS消化率**: エクスポート時点のsrsCardsスナップショットから、当該週にdueだったカードのうち消化済みの割合を近似する。週次の履歴を保持していないため、複数回同じ週に復習されたカードの扱いは概算になる。
- 数値のブレより「継続できているか（週5日など）」の傾向を見ることを優先する（06の4節: 継続指標が最重要）。

## あわせて記録すること（08の5.2節）

- 「SRSと弱点出題が体感として機能しているか」の主観メモを週次で残す。
- 悪問・音声の不自然さは `.github/ISSUE_TEMPLATE/bad-question.md` で記録する。
- iOSストレージ退避・データ消失の兆候が出た場合は即記録する。
