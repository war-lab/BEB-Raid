### 1.5 27の所見S-1の訂正

T-155の着手前に読むこと。27のS-1は機構を「`WebAudioPlayer.stop()` が `pendingResolve` を即解決するため」と書いたが、これは不正確である。

`AudioPlayer.play()` のインターフェース契約は「再生完了（または stop）で resolve する」と明記されている（`platform/audio/AudioPlayer.ts`）。`playSequence` も「途中で stop された場合は残りを再生せず resolve する」と定めている。つまり `WebAudioPlayer` は契約どおりに動いており、実装の誤りではない。

誤りは呼び出し側にある。`ShadowingScreen.handlePlay` が `await play()` の解決を「完走」と解釈して周回を加算している。契約が完走と中断を区別していないため、呼び出し側には区別する手段がない。

したがって修正はインターフェースの契約変更（T-155）が起点になる。S-2も同じ契約に起因するが、そちらは呼び出し側のクロージャ参照の誤りも併存するため、両方を直す必要がある。

## 3. 事前決定事項（J-89〜J-99の正文）

### 3.1 誤タップ救済の対象範囲と猶予時間（J-89）

**取り消し猶予の対象を、選択肢タップ以外の不可逆操作へ広げる**。現在の `UNDO_TARGET_FORMATS`（text_blank・audio_qa）に vocab_card の自己評価と語彙仕分けのスワイプを加える。dictation と audio_set は解答方式が異なるため対象外のまま置く（複数入力・サブ設問単位の確定であり、猶予の単位が定義できない）。

**猶予中も解説と「次へ」を描画する**。現在は `pending !== null` の間これらを出さないため全問に空白待ちが入る（S-8）。変更後は解説を即座に出し、「取り消し」を解説カードの上に並置する。取り消したときは解説を閉じて選択前の状態へ戻す。

**猶予時間は400msのまま変えない**。実測前に値を動かすと、H-16の計測が何を測っているのか分からなくなる。ただし空白待ちが消えることで400msの体感は変わるため、H-16では変更後のUIで計測する。

**ADR 0009にAmendmentを追記する**（ADR 0007の2026-07-27 Amendmentが先例）。対象範囲の拡大と猶予中UIの変更を記録し、「猶予中は解説を出さない」という当初の設計を上書きしたことを明記する。

### 3.2 解答制限時間は可変にしない（J-90。発起人承認）

15秒・6秒・先読み15/15/10秒はコード定数のまま維持する。設定UIも「ゆっくりモード」も追加しない。02の69-75行と99行の「型の強制」思想を変えない。

暫定値（6秒・400ms）の調整はH-16の実測後に行う。実測前に定数を動かさない。

### 3.3 リプレイ中はタイマーを止める（J-91。発起人承認）

「もう一度再生」の再生中は15秒タイマーを停止し、再生終了後に残り時間から再開する。聞き直しが解答時間の減少というペナルティになる状態（S-9）を解消する。

リプレイ回数の上限は設けない。上限を設けると別の圧を作るため、当面は無制限とし、必要ならH-16の実測後に再検討する。

実装は `isCountingDown` の条件に再生中を加える形になる。現在の条件は `isAudioQa && playState === 'played' && !result` で、リプレイは `playState` を変えないため成立し続ける。リプレイ中を表す状態を持たせて条件から外す。

### 3.4 時間切れはSRS登録を維持し表示で区別する（J-92。発起人承認）

`processWrongAnswer` によるSRS復習デッキ登録は今のまま維持する。時間切れで復習に入った問題を復習対象から外さない。

代わりにリザルトと統計で時間切れを別枠表示する。2026-07-29に実装した当て勘・速度不足の可視化と同じ様式に揃える。

環境要因の失点が復習キューに混ざることは許容する。学習機会を失う側の誤りより許容できるという判断である。

### 3.5 自動再生にopt-outを設ける（J-93）

2問目以降の自動再生（18のT-110で導入）を維持したまま、設定で無効化できるようにする。新キー `AUTO_PLAY_ENABLED_KEY = 'autoPlayEnabled'`（既定ON）を `settingsKeys.ts` に追加する。既定を変えないため、18のT-110の意図は保たれる。

あわせて**再生中の停止導線をUIに出す**。`audioPlayer.stop()` は実装済みでUIに露出していないだけである。ドリルの音声再生中と語彙仕分けのカード表示中の両方に置く。

語彙仕分けについては、画面内にイヤホンなしモードのトグルを置く（S-16。設定画面へ移動しないと切り替えられない状態を解消する）。

### 3.6 直近に解答した問題を出題候補から下げる（J-94）

`buildDrillCandidates` に「直近に解答した問題を後回しにする」規則を加える。除外ではなく優先度の引き下げにする。除外にすると小さいプール（Part2の150問）で候補が枯れるため、候補が足りないときは直近の問題も使う。

判定は `attempts` の `answeredAt` を見る。しきい値は**直近24時間以内に正解した問題**とする。誤答した問題はSRSと類題の経路で意図的に再出題するため対象にしない。

エンジンの純関数性を保つため、`attempts` の読み取りは呼び出し側で行い、`buildDrillCandidates` には解答済みIDの集合を引数で渡す（既存の `excludeQuestionIds` と同じ形）。

### 3.7 診断のフィードバックは終了後に一覧で出す（J-95）

初回診断30問の最中は正誤を出さない。診断は測定を目的とするため、途中でフィードバックを与えると後続問題に学習効果が乗り、レートの測定精度が落ちる。

代わりに**診断完了画面に30問の正誤一覧と解説への導線を追加する**。「当たったか外れたか分からないまま30問答える」という初回体験の問題（S-25）は、終了後に振り返れることで解消する。

あわせて診断中の画面に「正誤は最後にまとめて表示します」の注記を出す。フィードバックが無いことが意図的であると分かるようにする。

### 3.8 復習キューは20件ごとに区切る（J-96。発起人承認）

語彙SRSの復習フェーズを20件ごとに区切り、中間画面「復習を20件終えました（残りN件）」と「続ける/仕分けへ/ホームへ」を出す。仕分け側の `TRIAGE_BATCH_SIZE = 20` と対称にする。

**消化する件数の上限は設けない**。区切るだけで、キューそのものは期限到来分の全件を保持する。SRSの「期限が来たものは全部やる」思想（19の6節）は維持し、終わりが見えない表示だけを解消する。

19の6節の見送り記載を改訂する（「復習キューの上限・区切り」から上限のみを見送り事項として残す）。

### 3.9 イベントバトルの改修はクライアント側に限る（J-97。発起人承認）

`battleRoomDo.ts` の `QUESTION_OPEN_MS = 30 * 1000` は変更しない。問題種別ごとの秒数もホスト設定も導入しない。22のWebSocketプロトコルは無改訂とする。

クライアント側で対応するのは4点である。出題中・順位表示中の退出導線（S-33）、音声問題での問題文の補完（S-34）、解答後の解説表示（S-36前半）、未解答の記録（S-36後半）。加えてロビーに「1問30秒」の事前告知を出す（S-35のうちクライアント側で解消できる部分）。

未解答の記録は締切受信時に `isTimeout` のattemptを書く形で実現する。ソロ側の記録規則に揃え、`isCorrect` は false、`selectedIndex` は null にする。

### 3.10 同一セッション内の再挑戦（J-98）

「もう一回」を選んだカードを、同一セッション内のキュー末尾へ再投入する。DB上の `dueAt`（翌日0時）は変えない。1.3節の不変条件により間隔テーブルと `applyGrade` には触らない。

再投入は1周のみとする。2回目の「もう一回」では再投入せず翌日に回す。無限ループを避ける。

再投入で解いた分の `attempts` は通常どおり記録する。同一カードに対する複数のattemptは追記のみの原則に沿う。

### 3.11 3分クエストのフォールバック（J-99）

`quickPackConfig.json` の `durations["3"]` は `includeDrills: false` のままにする。SRS中心という構成の意図を変えない。

**SRSカードが0件のときに限りドリルを含める**フォールバックを加える。3分の枠に収まる問数（現行の `totalItems: 10`）でドリルから充当する。19のT-121で入れた案内文は、フォールバックでも0問になる場合（プール自体が空）のために残す。

02・03の該当節に「3分はSRSが空のときドリルで充当する」旨を追記する。

### T-155 AudioPlayerに完走/中断の区別を導入 🟢（単独PR）

- **対象所見**: S-1・S-2の前提。1.5節を必ず読むこと。
- **変更ファイル**: `platform/audio/AudioPlayer.ts`・`platform/audio/WebAudioPlayer.ts`・`platform/audio/WebAudioPlayer.test.ts`・`AudioPlayer` のテストダブルを持つ全テスト。
- **実装指示**:
  1. `type PlaybackOutcome = 'ended' | 'interrupted'` を定義し、`play()` / `playSequence()` / `replay()` の戻り値を `Promise<PlaybackOutcome>` に変える。
  2. `WebAudioPlayer` で、自然終了は `'ended'`、`stop()` による解決は `'interrupted'` を返すようにする。`pendingResolve` の型を変えることになる。
