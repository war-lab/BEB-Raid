# 07. ビジュアルデザイン

対象アプリ: **BEB Raid（Beat English Boss Raid／ビーブレイド）**。対象画面は [02_機能設計](02_機能設計.md) の画面一覧（S1–S10）。モックアップは別途Artifact参照。ロゴはリポジトリ直下の `logo.png`（鋼メタリック＋電光青のエンブレム）。

## 1. デザインコンセプト

**「静かな車内、熱いレイド」**

主戦場は満員電車。毎日使う道具の画面は静かで読みやすくなければならない一方、このアプリの魂はレイドバトルにある。この矛盾は「時間で分ける」ことで解く:

- **学習中（問題を解いている間）**: 演出を最小にする。派手な色・アニメーション・効果音的表現を置かない。周囲の目がある車内で恥ずかしくなく、集中を妨げず、バッテリーを消費しない。
- **区切りの瞬間（正誤確定・セッション完了・討伐）**: ゲームが顔を出す。ダメージ数字、HPバーの削れ、ストリーク炎はここに集約する。

世界観のモチーフは**夜行列車**。ベースは夜の車窓の紺、アクセントは金（金フレ・経験値・ダメージ）、レイドの緋がそこに差す。

## 2. デザイン原則

1. **親指第一**: 全ての操作要素は画面下半分（親指リーチ内）。上半分は表示専用。つり革姿勢で片手完結（02の2.2）。
2. **一画面一アクション**: どの画面にも「次にやること」のボタンは1つだけ大きく置く。起動→今日のクエスト開始が常に最短。
3. **静かな学習、騒がしい報酬**: 演出は区切りにまとめる。1問ごとの正誤フィードバックは150ms以内の控えめなもの、レイドダメージの演出はセッションリザルトで一括再生する。
4. **色に頼らない**: 正誤・状態は必ず 色＋アイコン/形 の二重符号化。色覚多様性・プロジェクター投影・グレースケール印刷で破綻しない。
5. **ダーク基調・ライト対応**: 既定はダークテーマ（車内で眩しくない・OLED節電・夜行列車の世界観）。ライトテーマも同等品質で提供する（昼・屋外・好み対応）。OS設定追従＋手動切替。

## 3. カラーシステム

トークンはCSS custom propertiesで定義し、コンポーネントは必ずトークン経由で参照する（テーマ切替を`data-theme`属性で行うため）。

### 3.1 グラウンド・インク（ダーク既定 / ライト）

| トークン | 役割 | ダーク | ライト |
|---|---|---|---|
| `--bg` | 画面地 | `#0E1220`（夜の紺、青バイアス） | `#F6F5F1`（暖白） |
| `--surface` | カード面 | `#181E31` | `#FFFFFF` |
| `--surface-2` | 入れ子面・押下面 | `#222A44` | `#EFEDE6` |
| `--line` | 罫線（ダークは影でなく罫線で層を作る） | `#2C3552` | `#DDD9CE` |
| `--ink` | 主文字 | `#EAEDF6` | `#211E18` |
| `--ink-2` | 補助文字 | `#A6AEC6` | `#6D675C` |
| `--ink-3` | 弱文字・プレースホルダ | `#6B7492` | `#9C958A` |

グレーは無彩色にせず、ダークは青へ・ライトは暖色へ寄せる（地色と同族に）。

### 3.2 ブランド・モードアクセント

| トークン | 役割 | ダーク | ライト |
|---|---|---|---|
| `--gold` | ブランド主色。主ボタン・ストリーク・XP・ダメージ数字・語彙（金フレ型） | `#F5B83D` | `#A66E00` |
| `--raid` | レイド・ボスHP・攻撃イベント | `#E8506B` | `#C42B4C` |
| `--listen` | リスニング系モード（Part2瞬発・ディクテ・シャドーイング） | `#4EC3E0` | `#0083A6` |
| `--violet` | 予測・SRS/復習系の識別色 | `#8B79E8` | `#6A55D8` |
| `--ev-blue` | ブランド表層（電光青）。ワードマーク周辺・英字ラベル・ヒーローのアクセント | `#4D8DFF` | `#2456C4` |
| `--steel-hi/-mid/-lo` | 鋼グラデ（ワードマーク文字用。`--wordmark-grad`で合成） | `#E8ECF4`/`#9AA6BC`/`#5B667E` | `#5A6478`/`#465064`/`#2E3648` |

- ダークの`--gold`上の文字は`#1A1405`（濃色）を使う。明るいアクセント上に白文字を置かない。
- モード色は画面全体を染めない。ヘッダーの細いアクセントライン・アイコン・進捗バーだけに使い、地は常に`--bg`。
- ブランド表層（ロゴ・ワードマーク・ヒーローカード）は鋼＋電光青、金はCTA・XP・ダメージ・ストリークの「報酬の色」に集約する（旧未決事項1の①案を [20_ビジュアル刷新計画](20_ビジュアル刷新計画.md) で確定。2026-07-22）。深度表現（面グラデ・光暈）のトークンと適用限定箇所は20の3.1〜3.2節が正本。

### 3.3 ステータス色（正誤・状態）

| トークン | 役割 | ダーク | ライト | 併用する形 |
|---|---|---|---|---|
| `--ok` | 正解・討伐成功 | `#3DC97E` | `#1E8A54` | ✓アイコン |
| `--ng` | 誤答 | `#F0647A` | `#C42B4C` | ✕アイコン |
| `--warn` | SRS期限超過・注意 | `#F5B83D` | `#A66E00` | ⚠/件数バッジ |

ステータス色はチャートの系列色に流用しない。正誤は必ずアイコンを伴う（原則4）。

### 3.4 チャート用カテゴリカルパレット（検証済み）

`validate_palette.js`（datavizスキル）で 明度帯・彩度床・CVD分離・地色コントラスト の全チェックPASSを確認済み:

- **ダーク面用**: `#B87F15`（金）/ `#2F97B4`（青緑）/ `#E8506B`（緋）/ `#8B79E8`（菫）
- **ライト面用**: `#A66E00` / `#0083A6` / `#C42B4C` / `#6A55D8`

UIアクセント（3.2）とチャート系列色は別トークンにする。ダークのUI金`#F5B83D`は系列色としては明るすぎるため、チャートでは必ず上記を使う。色の割当は固定（金=自分/主系列、青緑=リスニング、緋=レイド、菫=予測）で、系列数が変わっても塗り直さない。

### 3.5 ランク色（成長ランク）

| トークン | ダーク | ライト |
|---|---|---|
| `--rank-bronze` | `#B0805B` | `#8A5C37` |
| `--rank-silver` | `#AEB6C6` | `--steel-mid`（`#465064`） |
| `--rank-gold` | `--gold` | `--gold` |
| `--rank-platinum` | `#7FD6D0` | `#0E6B66` |
| `--rank-master` | `--violet` | `--violet` |

バッジは色＋段数刻み（台座の線の本数。ブロンズ1・シルバー2・ゴールド3・プラチナ4・マスター5）で二重符号化する。グレースケールでも本数からランクが判別できる状態を保つ。

ライト値はダーク値のままだと白面でAA未達になるトークンにだけ与えている。`--rank-platinum` のダーク値`#7FD6D0`は`--surface`（白）比1.689:1で読めないため、`#0E6B66`（同6.337:1・`--bg`比5.809:1。機械計算値）を追加した。

`--rank-master` には使用制限がある。ダーク値`#8B79E8`は`--surface-grad`上端`#1C2339`に対し4.447:1で本文基準4.5:1を満たさない。`--fs-display`（40px）のランク名に使う場合は大文字基準3:1で適合するが、注記・本文サイズの文字に同じ色を使ってはならない。

## 4. タイポグラフィ

### 4.1 書体

| 役割 | 書体 | 理由 |
|---|---|---|
| 和文UI・和訳 | システムフォント（`system-ui` → Hiragino Sans / Noto Sans JP / Yu Gothic UI） | 日本語Webフォントは数MB級でオフラインキャッシュ予算（100–200MB、大半は音声に割く）を圧迫する。同梱しない |
| 英文問題文・選択肢 | 同上のシステムサンセリフ | 可読性最優先。問題英文は装飾しない |
| ディスプレイ（ダメージ・HP・タイマー・スコア・ストリーク数・ワードマーク・英字ラベル・ボス名） | **Chakra Petch Bold** を英数字＋記号（ASCII可視文字＋`×`）にサブセット化して自前ホスト（WOFF2で約6KB。生成: `packages/app/scripts/subset-font.mjs`） | ゲーム感の演出をこの1書体に集約する。当初は数字のみだったが、ビジュアル刷新（20のV-2）で英字ラベルへ適用拡大した。ラテン文字のみなら容量・ライセンス（SIL OFL）とも問題ない |

### 4.2 タイプスケール（px、行間）

`12(注記) / 14(補助) / 16(UI標準) / 18(英文問題文, lh1.65) / 22(見出し) / 28(セクション数値) / 40+(ダメージ・タイマー等ディスプレイ数字)`

- 英文問題文は**18px以上・行間1.65・最大幅約34em**。揺れる車内で読む前提で、一般的なアプリ本文より1段大きくする。
- 数字が縦に並ぶ箇所（貢献ログ・統計）は `font-variant-numeric: tabular-nums`。
- 設定に文字サイズ3段階（標準/大/特大）を持つ。英文問題文にのみ適用でもよい。

### 4.2.1 投影用スケール（S8 イベントバトルホスト画面のみ）

上のタイプスケールはpx固定でスマホ向けである。プロジェクター投影は視距離と画面サイズが端末と無関係に決まるため、S8ホスト画面だけは `vw` 基準の別スケールを持つ（2026-07-28・[25の4.3節](25_ビジュアル刷新計画_M4以降の未適用画面.md)）。

`問題文 5vw以上 / 選択肢 4vw以上 / 順位の得点 6vw以上 / 進行位置・残り時間 2vw程度 / 英字ラベル・注記 1.6vw程度`

- 下限は `max(Nvw, Mpx)` の形で与え、ウィンドウが狭いときもpx下限で崩れないようにする。vw側が下限になるため、規定の比は常に満たされる。
- 実装は `components.css` の `.battle-host` スコープのCSSカスタムプロパティ（`--host-fs-*`）で持ち、`tokens.css` のグローバルトークンは増やさない。この画面以外は従来の `--fs-*` を使う。
- 地色はライトテーマのトークンをそのまま使う（プロジェクターは黒を投影できないため明地固定。[25のJV-6](25_ビジュアル刷新計画_M4以降の未適用画面.md)）。実装はホスト画面の表示中だけ `data-theme` をライトへ固定し、離脱時に元のテーマへ戻す方式で、AA検証済みのライト値を流用する。

## 5. レイアウト

### 5.1 画面の縦3分割（スマホ全画面共通）

```
┌──────────────────────┐
│ ステータス帯（表示専用）      │ ← 進捗・残数・タイマー・HPバー
│──────────────────────│
│ コンテンツ（表示専用）        │ ← 問題文・音声・カード
│                      │
│──────────────────────│
│ 操作ゾーン（画面下 約45%）    │ ← 解答ボタン・主アクション
│   ＋ iOS セーフエリア        │
└──────────────────────┘
```

- 操作ゾーンの原則: タップ目標は最小48px、**解答ボタンは高さ56px以上**・ボタン間8px以上。
- スワイプは左右のみ（02の2.2）。上下スワイプに機能を割り当てない（スクロールと誤爆するため）。
- 8ptグリッド（余白・サイズは8の倍数、微調整のみ4）。
- 角丸: カード16px / ボタン12px / バー類はピル。ダークテーマは影を使わず`--line`の罫線と面の明度差で階層を作る。
- **例外**: S8 イベントバトルホスト画面のPC表示（プロジェクター投影）にはこの縦3分割・操作ゾーン下45%を適用しない（7節S8・4.2.1節）。タップ目標48pxはこの例外でも維持する。

### 5.2 PWA外装

- `theme-color`はダーク`#0E1220`・ライト`#F6F5F1`をメタで切替。standalone表示、セーフエリアは`env(safe-area-inset-*)`で吸収。
- アプリアイコン: `logo.png` のエンブレムを夜紺`#0E1220`のタイルに載せて生成する。ホーム画面アイコンの小サイズ（48–60px相当）ではフルロゴは潰れる可能性が高いため、「BEB」部のみの切り出し版が必要になる見込み（要実機確認）。マスカブルアイコン（Android）用にセーフゾーン内収めの別書き出しを用意する。

## 6. コンポーネント規定

| コンポーネント | 規定 |
|---|---|
| 主ボタン | `--gold`地＋濃色文字、高さ56px、全幅。1画面に1つ |
| 選択肢ボタン（A–D） | `--surface`地＋`--line`枠、左端に丸囲みの選択肢記号。状態: 押下=`--surface-2`／正解=`--ok`枠＋✓／誤答=`--ng`枠＋✕／他選択肢=減光。**正誤表示時もレイアウトを動かさない**（枠色とアイコンだけ変える） |
| ボスHPバー | ピル形。残HPは`--raid`、削れた部分は`--surface-2`。直近の自分の寄与分を明るい金でハイライト。数値は`残HP/総HP`をディスプレイ数字で併記 |
| セッション進捗 | 画面最上部の細バー（2px）＋「7/12」残数表示。ドット列は10問超で破綻するため使わない |
| ストリーク | 炎アイコン＋ディスプレイ数字。増加した瞬間だけ炎が一拍揺れる。**切れそうな時に脅し演出をしない**（02の7「やらないこと」） |
| 音声プレイヤー | 再生/停止・3秒巻き戻し・速度ピル（0.7/0.85/1.0/1.15/1.3）・スクリプト表示切替（非表示→英文→英文+和訳）。すべて操作ゾーン内に配置 |
| カラオケハイライト | 発話中の語を`--gold`の下線＋やや明るい文字色で追従。読了語は`--ink`、未読語は`--ink-2`。背景塗りは揺れる車内でちらつくため使わない |
| スワイプカード（語彙） | 右=知ってる（✓が右端に出る）／左=知らない（→SRSへ、✕が左端に出る）。方向は左右対称の判定なので利き手設定は不要。下部に同機能のボタンも置く（スワイプ苦手対応） |
| ダメージトースト | 問題正解時、画面上部に小さく「+124」だけ。アニメーションは200ms。派手な演出はリザルトで |
| バッジ | 行動ベース名（「Part2 100問」等）＋取得日。未取得はシルエット表示 |

### ボスのアートディレクション

イラストを外注・都度制作する運用は回らない（コンテンツはLLM＋TTSの自動パイプラインで量産される前提）。ボスは**シードから生成するジオメトリックな紋章（シジル）**とする: 多角形・軌道環・目状の核をシード値から合成したSVG。週次ボス・ゴーストボスをコード生成で無限に量産でき、容量ゼロに近く、夜行列車×星座的な世界観にも合う。ゴーストレイドではボス役の表示名と紋章を併記する（顔写真・アバターは求めない）。

## 8. データ可視化規定

datavizスキルの手順に準拠。系列色は3.4の検証済みパレットのみ使用。

- **伸びグラフ（S6）**: 折れ線1系列（金）＋予測スコア帯は菫の低透明度の面＋破線境界。単系列なので凡例なし（タイトルが系列名）。終端点を強調しdisplay数字で現在値を直付け。二軸チャートは作らない。
- **弱点マップ（S5/S6）**: **レーダーチャートは使わない**。面積の錯覚で比較精度が低く、Part数（軸数）の変化にも弱い。代わりに**弱い順にソートした横棒**（Part/タグ別、ハンディ換算の弱点スコア）。レイド画面ではボス防御パターンとの対応をチップで併記。
- **学習ヒートマップ（S6）**: 金の単色シーケンシャルランプ5段（ダーク: `--surface-2`→`#B87F15`系を明度単調に）。GitHub草式。0日はセル枠のみ。
- 共通: グリッドと軸は退行色（`--ink-3`以下）、値ラベルは全点に振らず端点・極値のみ、ツールチップ必須、数表ビュー（またはアクセシブルな代替）を用意。

## 9. モーション

| 種別 | 時間 | 用途 |
|---|---|---|
| マイクロ | 120–200ms | ボタン押下・正誤枠・ダメージトースト |
| 画面遷移 | 250ms | スライド/フェード。学習中の遷移は最短に |
| 報酬演出 | 600–900ms | リザルトのダメージ一括加算・HP削れ・討伐・ランク昇格・イベントバトル最終リザルトの表彰。ここだけ豪華にする |

- イベントバトル最終リザルトの表彰（3位→2位→1位→ベストグロース賞の段階開示と得点のカウントアップ）は報酬演出に含め、総時間を600–900msに収める（2026-07-28・JV-4。[25の4.2節](25_ビジュアル刷新計画_M4以降の未適用画面.md)）。1位の得点には光暈（`--glow-gold`）を当てる。光暈の適用限定箇所は [20の3.1節](20_ビジュアル刷新計画.md) が正本で、同節の「リザルト数字」にイベントバトルの1位の得点を含める。
- `prefers-reduced-motion` では報酬演出を静止画＋数値表示に置換（機能情報を失わない）。JSタイマーで駆動する段階開示はCSSの全停止ルールでは止まらないため、`matchMedia('(prefers-reduced-motion: reduce)')` を見て静止表示へ縮退する。
- 学習中の常時アニメーション（背景ループ・波形の常時描画等）は禁止。バッテリーと集中の両方を削る。

## 10. アクセシビリティ・環境対応

- コントラストはWCAG AA（本文4.5:1、大文字・UI部品3:1）を両テーマで満たす。
- 正誤・選択肢・ランクは色単独に依存しない（アイコン/形/段数を併用。原則4）。
- 音に依存しない: イヤホンなし時のリーディング差替（02の2.2）に加え、全フィードバックは視覚で完結させる（正解音などを入れる場合も視覚と等価に）。
- フォーカスリング可視（キーボード/スイッチ操作）、`tabular-nums`、文字サイズ設定（4.2）。
