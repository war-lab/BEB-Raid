[16](16_M3タスク分解.md)/[17](17_M3実装計画.md)・[21](21_M4タスク分解.md)/[22](22_M4実装計画.md) はタスク分解と実装計画を2冊に分けたが、本件は6タスクと小規模なため1冊に統合する。

## 2. 設計方針（T-132でADR化する）

1. **抽象化レイヤの実証**: 本件は T-04 で用意した platform 層（AudioPlayer・PackCache）と、M2で追加した AiClient が想定どおり差し替え可能かを実地に確認する作業でもある。UI・エンジンの改修が必要になった場合、それは抽象化の失敗を意味するため、回避策を書く前に停止して設計を見直す。
2. **不変条件は変わらない**: オフライン正常系・attempts追記のみ・プライバシー境界・コンテンツの license/origin は、ネイティブ化で一切変更しない。通知は端末内で完結させ、共有APIへ新しい送信経路を作らない。
3. **Web版を落とさない**: GitHub Pages配信のPWAは継続する（J-74）。ネイティブ側の変更でWeb版のビルドやテストが壊れた状態を完了とみなさない。
4. **費用の上限**: Apple Developer $99/年 のみを想定する。これを超える支出（ストア公開・有償プラグイン・有償CI枠）が必要になったら停止する。

## 4. 全タスク共通ルール

[22の2節](22_M4実装計画.md)（上流は 17・13・10 の2節）を継承する。本書での差分は以下のとおり。

### 4.1 ブランチ運用

`task/T-1xx-説明` ブランチを dev から切り、dev へドラフトPRを出す。dev直コミットはしない。

worktreeで作業する場合、**worktree直下で `npm ci` を実行してから始める**（T-123で、worktree直下に node_modules が無いとNode解決が親ディレクトリのnode_modulesへ抜け、メインチェックアウト側のdistを参照してビルドが誤って壊れる事象を確認済み）。

### 4.2 新規依存の方針

本書は例外的に**新規依存の追加を伴う**（`@capacitor/core`・`@capacitor/cli`・プラットフォーム別パッケージ・`@capacitor/local-notifications`・音声プラグイン）。

追加してよいのは上記の範囲に限る。これ以外が必要になったら停止して確認する。

### 4.3 回帰確認（毎タスク）

1. Web版のビルド（`npm run build`）とテスト（`npm test`）が通ること。
2. `VITE_RAID_API_BASE_URL` 未設定（API無効）のとき、ソロ学習の動作・表示が一切変わらないこと。
3. 端末外へ出るデータが増えていないこと（通知は端末内完結）。

### 4.4 停止規則

- UI・エンジン（`screens/`・`engine/`）の改修が必要になったとき（抽象化レイヤの失敗を意味するため。設計方針1）。
- 音声プラグインが `rate`・`onPosition` の要件を満たさないとき（J-77）。
- $99/年を超える支出が必要になったとき（設計方針4）。
- 完了条件を1つでも満たせないとき（条件を緩めず報告する）。
