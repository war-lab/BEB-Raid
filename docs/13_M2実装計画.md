### 3.1 criteriaJson スキーマ（J-17）

`phase.criteriaJson` は次の形式。全条件AND（`all`）のみ（OR は M2 では作らない）:

```json
{
  "all": [
    { "type": "srsRetention", "minRank": "S", "min": 0.85 },
    { "type": "accuracy", "scope": { "part": 2 }, "min": 0.7, "window": 100 },
    { "type": "setAccuracy", "min": 0.6, "windowSets": 20 },
    { "type": "examScore", "minTotal": 760 }
  ]
}
```

- `srsRetention`: 対象ランク語彙のうち**導入済み**（introducedDate≠null）カードに占める「定着」カードの割合。**定着 = stage≥2（間隔7日以上に到達）または graduatedAt≠null**（`SRS_INTERVAL_DAYS = [1,3,7,14,30,60]` のインデックス2以上）。導入済みが20枚未満の間は未達扱い（ノイズ対策）。
- `accuracy`: attempts の直近 `window` 問（`scope` は part 番号 or タグ名。`vocab:`/`shadow:` プレフィックスは除外）に対する正答率。該当 attempts が window の半分未満なら未達扱い。
- `setAccuracy`: audio_set の直近 `windowSets` セットに対する「セット正解」（1セット3問中2問以上正解）の割合。セット数が windowSets の半分未満なら未達扱い。
- `examScore`: examScores ストアに `total >= minTotal` の登録があるか。

### 3.2 カリキュラム（J-16 / J-18 / J-19）

- **フェーズ条件**: P1→P2 = `srsRetention(S)≥0.85 AND accuracy(part2)≥0.70`（03の1.2既定）。**P2→P3 = `srsRetention(A)≥0.75 AND setAccuracy≥0.60(20セット) AND accuracy(part5)≥0.70`**。P3は自動卒業なし。`examScore(total≥760)` 成立で「シーズンクリア」表示＋バッジ（badges ストア初使用）。
- **L段階条件**: L1→L2 = `accuracy(tag:弱形・連結)≥0.75(直近100問)`、L2→L3 = `accuracy(part2)≥0.70`、L3→L4 = `setAccuracy≥0.60`。L4 は終端（倍速1.15x以上の解禁のみ）。
- **初期割当**: P0診断（または自己申告換算）の総合レート R<550→P1、550≤R<650→P2、R≥650→P3。L は常に L1 から（リスニングは段階スキップさせない。03の8節の思想）。M1からの既存ユーザーは phase レコード不在のため、M2初回起動時に現在の ratings から同式で1回だけ割当てる。
- **phase レコード**: `{ season: 'P1'|'P2'|'P3', listeningStage: 1|2|3|4, criteriaJson, achievedAt }`。移行判定はセッション完了時（ResultScreen 表示時）に評価し、成立したら phase を書き換えて移行演出を表示する。
- **配分合成**（generateQuickPack 拡張）: ①SRS期限（cap 15/パック、既存）→ ②残り枠を現フェーズの allocation で比例配分（最大剰余法）→ ③リスニング枠の内訳を L 段階で決める（L1: dictation 40%/shadowing 30%/part2 30%、L2: part2 100%、L3: part3・4セット70%/part2 30%、L4: L3と同じ＋倍速可）→ ④枠内の問題選択は既存の弱点タグ・key単語 1.5倍重み。
  **2026-07-18改訂**: shadowing形式はドリルセッションに割り当てない（DrillScreenに解答UIが存在せず、混入するとセッションが進行不能になる不具合が実機で発生したため）。シャドーイングは専用画面（S4）での実施に置き換え、L1のshadowing枠は既存の在庫不足時再配分の仕組みでリスニング枠内の他形式（dictation・part2）へ流れる。DrillScreenでのshadowing出題を再開する場合は、専用の解答UI実装とセットで行うこと。
- **フェーズテンプレ**は `engine/curriculumConfig.json` に外出し（quickPackConfig と対）。**M2暫定テンプレ**（コンテンツ在庫制約。03の1.2の理想配分との差は同ファイルの $comment に明記）: P1 = 語彙50/リスニング25/part5 25、P2 = 語彙25/リスニング40/part5 35（03のPart7シングル15%枠はコンテンツ未整備のため語彙・part5へ振替=J-9）、P3 = 弱点補強50/リスニング30/part5 20（ミニ模試・Part7マルチはM3以降）。

### 3.3 予測スコア・到達予測（J-15）

- 予測TOEIC = 総合レート×0.99、**±50の帯**で表示（03の5.5既定。中心値の断定表示はしない）。
- **到達予測**: ratingHistory（section='total'）の直近28日を最小二乗の線形回帰し、傾き s（レート/日）を得る。目標レート = 768（760×1000/990）。
  - データが14日分未満 → 「計測中（あとN日）」
  - s>0 → 到達日数 = (768−現在レート)/s。**月粒度**で「このペースなら YYYY年M月頃」（±の幅は出さない。「参考値」注記必須）
  - s≤0 → 「このペースでは到達しない」＋不足量: 90日で到達するのに必要な傾き s* = (768−R)/90 を出し、現ペースの「1学習日あたり平均上昇」から**「週の学習日数をあとN日増やす」**換算で表示（N は切り上げ、最大7）
- 実試験スコア登録（examScores）は S6 から。予測との乖離は登録一覧に併記表示のみ（モデル校正はM3以降）。

### 3.4 ディクテーション（J-12 / J-29）

- **ワードバンク方式のみ**。バンク = 正解語（blanks の answer）＋ダミー語で計6語（穴が複数なら正解語N＋ダミー(6−N)）。ダミーは同一パック内の他問題の blanks 正解語から品詞・音の近いものを優先し、不足分は頻出機能語プール（`engine/dictationDistractors.ts` に静的定義: would/should/could/them/their/there/for/from 等の弱形・混同ペア）から補う。
- **採点**: 全穴一致で正解、1つでも不一致で誤答（部分点なし）。大文字小文字は無視。attempts は通常記録・**レート更新はスキップ**（J-29）・tagStats は記録（弱形タグが L1 判定の入力）。
- blanks は1問1〜3穴。再生は L1 中 0.85x を選択可（03の8節）。
- **バリデータ（C-1）**: `blanks[].index` が script の語数（空白区切り）未満、かつ `blanks[].answer` が script の該当位置の語と一致（大文字小文字無視・前後の句読点 `.,?!;:'"` を除去して比較）。

### 3.5 シャドーイング（J-13 / J-23 / J-26）

- **記録規約**: 1素材の再生完了（最後まで到達 or 3周）で attempts に1件追記 — `questionId: 'shadow:<questionId>'`・`mode: 'solo'`・`isCorrect: true` 固定。レート・tagStats・SRS の対象外（集計側は `vocab:` と同様に `shadow:` プレフィックスで除外。cli の calibrate にも除外を追加）。ストリーク成立にはカウントする。
- **カラオケハイライト**: timing（単語開始msの配列）で現在再生位置の語を強調（07の6節131行の規定: `--gold` 下線＋明るい文字、読了語 `--ink`、未読 `--ink-2`、背景塗り禁止）。再生位置は `PlayOptions.onPosition`（3.7節）から得る。timing が無い素材は文単位ハイライトに縮退。「ハイライトは目安」の注記を画面に置く。
- **区間リピート**: 文単位のみ。script を文境界（`.` `?` `!`）で分割し、timing から各文の開始msを導出。文をタップで選択→その文をループ再生。
- **速度**: 0.7/0.85/1.0/1.15/1.3。**1.15以上は listeningStage=4 でのみ表示**（03の8節）。
- **timing 生成（cli）**: Piper は単語タイムスタンプを出力しない前提（B-4。T-46 冒頭で実挙動を確認し、公式に取得手段があればそちらを採用してよい）。推定方式: 単語ごとの重み = 音節数近似（母音クラスタ数、最低1）＋固定オーバーヘッド、文末句読点に一時停止重みを加算し、実測 durationMs を重み比で按分。検証条件: 単調増加・先頭0付近・末尾≦duration。

### 3.6 先読みトレーナー / audio_set（J-10 / J-24）

- audio_set の通常出題（T-49）: 音声1本再生→設問を1問ずつ順次解答。attempts は **subQuestion.id 単位**で記録する（生成時のID規約: `<questionId>-q<n>`）。tagStats・レート更新は通常どおり（選択式）。「セット正解」= 同一セットで2/3問以上正解（エンジンが attempts から setId 部分で導出）。
- 先読みトレーナー（T-50）はセットモードの拡張フロー: **①先読みフェーズ**（設問・選択肢を表示、音声なし、残り秒数表示。P2=15秒/P3=10秒=J-24。満了で自動的に②へ。「もう再生する」で早期開始可）→ **②再生フェーズ**（スクリプト非表示・一時停止/巻き戻し不可）→ **③解答フェーズ**（設問1問ずつ）。
- L3 のクイックパック配分ではセットは常に先読みフロー付きで出題する（「型の強制」= 02の3.5）。

### 3.7 platform 拡張（J-27 / C-3）

- `PlayOptions` に `onPosition?: (positionMs: number) => void` を追加（再生中の現在位置通知。実装は 100ms 間隔程度で十分。rAF でも可）。
- `rate` を予約から本実装に昇格。**実装方式: rate≠1.0 指定時のみ HTMLAudioElement 経路**（`playbackRate` ＋ `preservesPitch`/`webkitPreservesPitch`）を WebAudioPlayer 内に併設。`AudioBufferSourceNode.playbackRate` は使わない（ピッチが変わる）。preservesPitch 未対応環境はピッチ変化を許容し、S4 に注記。unlock 済み AudioContext と HTMLAudioElement の自動再生制限は独立のため、rate 経路の初回再生もユーザータップ起点で行うこと。
- 新規 `platform/ai/AiClient.ts`:

  ```ts
  interface AiAskContext { question: string; choices: string[]; answer: string; explanation: string }
  interface AiClient {
    isConfigured(): Promise<boolean>
    ask(context: AiAskContext, userQuestion: string, history: { role: 'user' | 'assistant'; text: string }[]): Promise<string>
  }
  ```

  実装（`AnthropicAiClient`）は fetch で `https://api.anthropic.com/v1/messages` を直呼び（`anthropic-dangerous-direct-browser-access: true` ヘッダ。05の5節）。**実装時は claude-api スキル等で最新の安価モデルIDを確認し**、`DEFAULT_BYOK_MODEL` 定数に一元化（設定で上書き可）。max_tokens=1024。システムプロンプトに問題文・選択肢・正解・事前生成解説を含め、「TOEIC学習者向けに簡潔に日本語で」と指示。ESLint の直接WebAPI禁止対象には fetch を追加しない（運用ルールとして外部API呼び出しは platform 実装内に閉じる）。
